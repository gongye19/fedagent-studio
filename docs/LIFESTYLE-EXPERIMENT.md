# LifeStyle 首批正式实验（T148）

用户已确认开始首批：NIH／CDC／NHS各10篇不同文档的小节，生成30条公开资料的合成建议过程，经现有FoT聚合为一个经验包，再用同一模型对24道固定独立问题作无经验／加载经验两组对照。本轮不扩至96题、不新增算法、不部署。正式结果以末尾实际运行记录为准。

## 冻结输入和方法

- 原知识来自[T147](./LIFESTYLE-KNOWLEDGE.md)的固定30个编号；问题来自[T146](./LIFESTYLE-CORPUS.md)预选24个HealthBench对话和341条原始规则。选题不参考模型结果。
- 完整原文章、选定小节、来源／日期／人群／地域／许可随生成请求保留，评测对话和规则不进入生成。个人资料明确未知，不编造Synthea人物、医院或真实就诊。每条生成过程验证上传规范和来源摘要；events仅允许advisor，不造患者回答。
- 三组是公开知识分区，不是真实医院。每组10条，正常上传至本机隔离平台，复用`RecordFoT`读取、反思、最多3条trace、归类、`paper-auto`建库与发布；温度0.7、top_p0.9及原输出上限不变。只复用旧工具的`local_platform`与`checked`，不运行旧三方冒烟流程或额外本站库。
- 完成后核验30条记录各有1–3条实际trace，再发布本机成果。零trace检查在整个任务完成后，因此不能省掉已经发生的归类／建库调用。格式暂停、超预算等终态保留现场，续跑不再发模型请求，不通过改写算法或重建任务绕过。
- 默认调用配置为`default:gpt-5.6-luna`；检查过现有远端接口身份，不导出密钥。源资料、模型配置身份、执行代码与依赖版本、实际调用参数和请求哈希冻结；变化需新目录。旧395个实验文件及旧T146／T147冻结包保留。

## 预算与恢复

正常路径822次：30次过程生成、60次反思／提取、2次全局聚合；48次回答和682次逐条评分。另1次连接探测。**总硬上限850次**，含失败与格式修正，双路并发；生成／探测／FoT阶段先为评测预留730次，因此最多120次。评测首次开始前检查预留，之后最多使用850减去前段实际消耗的次数，不自动增额。

成功模型回复按完整请求／配置身份缓存，生成、回答、各条评分另存检查点；坏格式只作废自己的回复，每单元最多2次可能已计费的失败（含空回复、截断、格式错误和已开始SSH派发的传输失败），失败不当答错。已完成的生成／回答／规则不重算；逐规则先评两组再进行下一条。FoT内部保留原重试，缓存可能复用同一不合法回复，结构暂停按终态报告，不声称可以无限恢复。

旧运行器继续默认最多50次，新批次才显式使用850次上限。供应商窗口未核实；逐请求使用UTF8字节上界加输出token上限和预留作保守131072边界，超限未发送且不截断。实际接受请求的大小另记；这不是供应商窗口承诺。网关的协议回退可能在一次远程尝试内有额外HTTP请求，次数不是最终账单；报告实际token，不猜单价。

## 对照与评分

24个完整原对话不压成`profile/question`。独立对话适配器给两组同一系统提示、原始多轮上下文和同一模型，只有经验数据不同；按最后用户语言回答，本批问题为英文。它不是中文应用入口的逐字复现。每题两组顺序按固定种子打散；评分请求只看原对话加候选回答，不看组别和经验库。

评分提示逐字来自[OpenAI simple-evals](https://github.com/openai/simple-evals/blob/652c89d0ca9df547706735883097e9537d40dc47/healthbench_eval.py)，固定提交和SHA256，原代码／MIT许可归档在输入目录。只用AST读取字符串，不执行下载的代码。逐规则询问`criteria_met`，负分规则满足即扣分，不反转含义；每题`满足规则的带符号分数之和／所有正分规则之和`，单题不裁剪。另给原版方式裁剪至0–1的总体均值，主对照用未裁剪的完整配对均值。

评分模型换成当前同一模型、temperature=0、解释必须非空、格式尝试有限，均属于适配；不是官方HealthBench全量成绩、医生评审或临床正确率。两组都完整的题才进入配对均分／变好／持平／变差，仍报告全部24题分母及每组缺失数，扣分项不统一冒称安全项。不挑只提升的题，不把主题相关但非医学核验的公开知识当效果保证。

### 2026-11-18 实际结果

香港时间22:21:05至23:38:25，耗时约77分19秒。NIH／CDC／NHS各10篇资料生成30条建议过程，经真实本机上传、FoT反思／提取／归类／建库和发布，得到15条最终经验。30条过程各提取3条，共90条trace，不能把这90条或30份资料写成最终经验数量。

归类首次返回6个组，覆盖87条、遗漏3个编号，没有重复编号；第93次调用仅补齐这3项分配，随后成功建库，没有整份归类重跑。初次进度说明根据任务状态误称未修正，核对完整请求账本后已更正；`task.json`的空`algorithmLogs`不等于没有修正，实际证据见`verification/profile-repair.json`及第92–94次请求缓存。

24题全部完成，共48份回答和682份规则判定，无缺失。模型配置及实际返回均为`gpt-5.6-luna`。

| 同一24题、同一模型 | 原始规则配对均分 |
| --- | ---: |
| 无经验 | 48.82% |
| FoT联邦经验 | 49.34% |
| 差值 | +0.52个百分点 |

12题变好、7题持平、5题变差。满足负分规则的次数为29→26，但负分规则包含沟通／完整性等，并不统一代表医疗安全事件。单题有负分，未裁剪；总体均值已在0–1内，所以原版方式裁剪的总体值与上表相同。

**本批跑通了链路，没有证明明显总体提升。** 仅24道固定主题题，同模型自评，未重复采样或医生复核。事后描述性的配对bootstrap（固定种子、20000次）给出差值95%区间约−6.22至+6.40个百分点；它只重采样这24题，不是预注册检验或总体／临床效益结论。原自动分数原样保留，没有为了展示改分、换题或追加有利尝试。

核对了6个变化案例的回答与差异规则，属于内容／判分检查，不是临床审核：

- 胃肠不适恢复后的清淡饮食：66.04%→83.02%，经验组补充逐渐恢复饮食和症状复发时求助，规则差异有对应文字。
- 持续腰痛的运动安排：69.44%→77.78%，经验组补充避免过度反弓等动作限制，规则差异有对应文字。
- 轻度运动后补液：87.30%→47.62%，经验组少了若干易执行的具体信息，还加入规则扣分的体重补液公式；保留这一退步案例。
- 蛋白摄入题部分分差来自真实建议范围变化，但两组均提`lean meats and legumes`的食物来源规则被采取不同宽严口径。
- 老年人轻运动的+25点和卒中家庭康复的+17.39点均来自一条规则口径不一致：基线被要求包含所有例子，经验组却被允许部分例子。因此不能把它们作为已验证的明显提升展示。

这版经验主要是适用性判断、渐进计划、营养条件与来源边界等通用方法，不是把原文全部知识直接注入。收益不稳定的原因尚未通过额外实验定位；不把“经验过于通用”或“模型本身较强”等推测当成已证实原因。下一步应先统一评分核验口径、检查具体信息保留和适用经验选择，再决定是否扩量，而不是直接加更多相同调用。
