## 一句话状态

统一的维度分层已经落到前端：候选只保留最通用的主流方法和 Agent / 大模型相关方法，用户先选 4 个场景之一（按运行方式分为连接节点和上传文件两类），平台推导执行模式、联邦对象、runner 和保护机制，每个场景用自己的执行模式跑通七步模拟流程。真实节点连接、上传、Agent、沙箱、runner、评测和发布后端尚未接入。

## 已完成

### 维度与场景

- 3 个维度：场景（横向联邦训练含子项 1.1 模型类别、1.2 共享方式）、协作策略、安全与隐私；运行默认值不在界面展示，定义见 [DIMENSIONS.md](./DIMENSIONS.md)。
- 4 个场景：横向联邦训练（Flower）、纵向联邦训练（NVFlare）、联邦统计分析、Agent 记忆联邦。
- 7 条协作策略（只留最通用的，Agent 相关除外），各自声明计算类型、联邦对象、runner 和参考开源实现。
- 安全与隐私：基础保护 + 协议内置保护自动生效；可选增强（SecAgg+、差分隐私）只列策略所在 runner 实际提供的，可多选。

### 界面

- 配置步骤所有维度和候选项始终展开；上游选完后下游不支持的选项自动置灰（不显示原因）；唯一可选项自动选中；不显示成熟度、前沿或参考实现标注。
- 第一步先选场景（维度 1，按"连接节点 · 多轮运行 / 上传文件 · 一次完成"分组）；横向联邦训练的子项在同一张卡片里、各自成卡，选完场景后自动填好，可调整但不能取消；其他场景不显示子项。
- 已选选项再点一次即取消；再点一次当前场景即取消场景。
- 右侧"平台推导"面板实时显示场景、执行模式、联邦对象、计算类型、runner 和保护机制。
- 数据接入：列出数据要求；节点类场景勾选已连接的节点、给出我方节点启动命令并可模拟上线；文件类场景勾选已提交的文件，上传我方文件由 Agent 检查格式、字段和条数，不符合时逐项说明原因和建议，未通过前不能开始。
- 发布需要选择范围并手动确认，可以查看冻结的 FrontendRunPlan。
- 界面文案统一中文（步骤：配置、数据接入、准入检查、创建沙箱、执行、评测、发布）；选定场景后协作策略只列该场景的。
- 统一设计 token：字号不小于 11px，状态色文字对比度 ≥ 4.5:1，状态图标为 SVG；维度 1–3 是分区，只有场景子项保留圆角卡片。
- 桌面端与移动端均可用：手机端顶部显示步骤进度，操作栏吸底，触屏点击目标 ≥ 44px。

## 技术债务与风险

- 各策略的内置保护和可选增强目前写在前端注册表里，后端阶段应改为由 runner manifest 声明，前端只展示。
- 参与方、指标和产物都是演示数据，界面和文档必须持续标明"模拟"。
- 保护配置容易被误解为已实现安全能力。
- Agent 记忆联邦还没有公认的标准算法，合并、冲突处理和验证规则需要在 demo 里逐步定下来。
- 纵向只有安全纵向 XGBoost 一条策略；Flower 的纵向支持只到示例级别，所以用 NVFlare。
- 截图目录包含多轮历史设计，正式汇报使用 `dimension-*.png`。

## 下一阶段建议

### M1：确认分层

- 用当前前端评审维度、场景和依赖规则是否合理，调整后再冻结。

### M2：两个后端 demo

- 选两个运行方式不同的场景验证抽象：横向联邦训练（Flower，连接节点、多轮，可先用 LoRA）和一个上传类场景（联邦统计分析或 Agent 记忆联邦）。
- 每个 demo 打通真实输入 manifest、规则校验、本机隔离容器、执行、评测和产物登记。

### M3：平台化

- 定义 `RunSpec`、`InputManifest`、`PreflightReport`、`RunnerManifest` 的 JSON Schema，把前端注册表拆成版本化配置。
- 增加 API、PostgreSQL、对象存储、队列、身份和审计。

### M4：Agent 与安全能力

- Agent 解释结构化规则，并处理受控长尾问题。
- 按场景逐项落地 SecAgg+、DP，以及纵向的 PSI 和 Paillier。
