## 已完成（后端，T52）

- **插件体系**：算法、任务类型、判分方式是 Python 包，通过 entry points 发现；算法用 `manifest.yaml` 声明角色、步骤、交换通道、产出、评估和参数。平台按清单编排，并限制每一步能读什么、能发出什么：服务端步骤读不到数据集，标注默认不交给算法，没声明的通道发不出去。
- **FoT 插件**：六个步骤（解题、反思、提取经验、汇总、归类、生成经验库），上游 Prompt 1–5 逐字使用（用指纹测试固定），参数和复现器对应；`apply`（试用和 API）、导出（与 `library_r{n}.json` 同格式）。
- **数学推理任务类型**：数据检查和前端同一套规则；两种判分（论文的规则、只看最后一个 `\boxed{}`）。
- **编排**：每一步拆成工作单元，结果写进数据库后才推进；runner 常驻，每个运行中的任务一个子进程；暂停、继续、取消；子进程意外退出时从检查点重启，runner 重启时不会同时跑两个进程。
- **模型网关**：OpenAI 兼容接口，按接口限并发、自动重试；每次调用记账，续跑时从账本取回已完成的调用，不重复计费；密钥加密保存、只能写入；测试用假模型（只在本地开发和测试里有）。
- **本地客户端**：`fedagent-client` 用同一份插件代码在参与方本地执行，只提交声明可以离开的内容，`--review` 可以逐条确认；安装包由平台在 `/client/` 下提供。
- **API 和部署**：FastAPI，前端的类型从 OpenAPI 生成；可选的访问令牌（现在关闭）；一条命令部署到服务器（用户进程，不用 Docker 和 sudo）。
- **测试**：契约测试（数据流和清单一致、能续跑）、接口和完整流程、平台托管和本地客户端混合的任务、真实子进程的 runner。

## 已完成（前端）

### 场景、算法与数据

- 3 个场景：
  - 横向联邦 Agent：可用，算法是 FoT；
  - 纵向联邦 Agent、联邦迁移 Agent：规划中，只说明用途和所需数据。
- 算法注册表从后端读：FoT 声明了适用的任务类型、交换内容（解题经验）、产出（经验库）、4 个可调参数、每轮 6 步和每一步的预估用量；平台的预估、进度和任务推进都只按清单计算。
- A–H八个实际平台托管参与方，各持一份数学推理题库（AIME24、AIME25、AMC、CCEE、CNMO、WLPMC、V202412Hard、V202505Hard，共300题），全部导入可用；来源文件与哈希随代码保存，不再创建空示例合作方或手写样本。
- 概念分开：场景（各方的数据怎么分布）、任务类型（Agent 做什么）、算法（各方怎么协作）来自注册表；参与方（机构或节点，不绑定场景）和数据集（属于一个参与方，登记时选定场景和任务类型）由用户登记；联邦任务把它们组合起来，每个参与方出一份数据集。

### 页面

平台按通用情况设计：场景、任务类型、算法、算法参数、每轮步骤、交换内容、产出和预估用量都来自注册表，FoT 只是目前登记的算法。平台名称是 FedAgent Studio。导航和原 TrustFLAIR 平台一致：首页、联邦任务、应用、基础管理。

- **导航**：首页、联邦任务、应用、基础管理四个一级导航，同一个样式；基础管理点开后才出现参与方与数据、算法、模型接口。窄于 900px 时收进顶栏的"菜单"。
- **首页**：居中的"选择联邦场景"，三张卡片各带一张示意图（横向按样本分、纵向按字段分、迁移从已有领域到新领域）；可用的场景点进去就是这个场景的联邦任务配置，规划中的灰显。
- **分类**：联邦任务、应用、参与方与数据、算法都先按场景（横向 / 纵向 / 迁移）、再按任务类型分：前三个按场景分块、任务类型是表格的一列，算法按场景分栏；四个页面上方都可以按任务类型筛选。模型接口是共用的，不分类。
- **联邦任务**：按场景分块列出任务，每块右上角是这个场景的"新建联邦任务"，和首页点场景卡片进的是同一个配置页；名称搜索、任务类型筛选、状态筛选对所有场景一起生效。每个场景有自己的配置页，目前只做了横向联邦。
- **新建联邦任务**：
  - 依次选场景 → 任务类型 → 算法 → 参与方，每一步都由用户选，不预先填好；从首页点场景进来时场景已选好，页面只列这个场景的选项；
  - 任务类型和算法的选项最后都留一个"待接入"的空位，表示之后还会有别的；
  - 参与方表格一行一个参与方，只列出登记了同一场景、同一任务类型数据集的参与方，每方出一份（名下有几份时在行里选），表头可以全选；还不能参加的（等待连接、离线、样本待导入）写明原因，排在后面；
  - AWS 控制台风格：配置面板里字段名在上、两栏对齐，控件下方不放说明，需要解释的字段点"说明"展开；
  - 只有一个模型时直接写出来；右侧配置摘要和后端算出的预估；模型接口没配好时写明还需要什么；
  - 算法参数按注册表生成，收在"高级配置"里；
  - 中途可以去新增参与方、数据集或配置接口，保存后回到这里；新数据集和任务匹配时直接选入；
  - 窄屏时创建按钮吸底，正式运行的确认也在底部栏；有"取消"，动过的配置要确认才放弃。
- **任务详情**：概览（本地 vs 联邦、负迁移、产出、各方变化、明细）、进度（按算法定义的步骤、各方进度、真实的通信记录）、产出（每轮一版，发布时填应用名称）、配置（冻结的配置、算法参数、参与方快照）；可以暂停、继续、取消（原地确认）、复制为新任务；用假模型跑的标"假模型"。
- **应用**：任务产出发布后的成果；按场景分块，表格列出应用、任务类型、产出（算法）、来源任务、发布时间，可以按名称搜索、按任务类型筛选；分类在发布时记下，来源任务删掉后不变。详情里试用（不带 / 带应用各调用一次模型，填了标准答案时判分）、内容、接入（导出 JSON、API）；可以重命名、撤下。
- **基础管理**：
  - 参与方与数据：一个页面，按场景分块（横向 / 纵向 / 迁移），每块一张表，只写参与方、数据集、任务类型、样本数（参加了哪些任务不在这里显示）；可以按名称搜索、按任务类型筛选；点开一行看数据集详情、本地客户端的安装和连接命令（签发令牌）、新增数据集、删除；每个参与方至少留一份数据集；
  - 新增参与方、新增数据集都是独立页面：运行位置、场景、任务类型都由用户选，然后上传文件（平台托管，在浏览器里先检查格式，后端再查一次）或登记名称（参与方本地）；
  - 算法：按场景分三栏列出算法卡片，每栏最后是"待接入"的空位，可以按任务类型筛选；点开是算法详情页（概况、每轮步骤、参数的默认值和说明、来源）；
  - 模型接口：只登记真实接口（测试用假模型只在本地开发和测试里有）；每个接口从接口提供的模型里选一个，列表只写选用的模型；新增、编辑是独立页面，密钥加密保存、只能写入，测试连接按任务实际的参数检查；登记的接口可以删除。
