# 当前进展

更新时间：2026-09-24
版本：0.2.0 前端原型

## 一句话状态

统一的维度分层已经落到前端：候选只保留主流方法和大模型 / Agent 相关方法，用户逐层选择即可到达 8 个场景模板中的一个，平台推导执行模式、联邦对象、runner 和保护机制，每个场景用自己的执行模式跑通七步模拟流程。真实上传、Agent、沙箱、runner、评测和发布后端尚未接入。

## 已完成

### 维度与场景

- 4 个维度：场景（子项 1.1 协作目标、1.2 各方投入、1.3 数据关系、1.4 参与方形态、1.5 模型类别、1.6 共享方式）、协作策略、安全与信任、场景参数，定义见 [DIMENSIONS.md](./DIMENSIONS.md)。
- 8 个场景：模型联合训练、LoRA / Adapter 联邦微调、模型与 Adapter 聚合、纵向联合建模、联邦评估、联邦统计分析、FedRAG、Agent / Skill 协作。
- 23 条协作策略，各自带标注（主流 / 前沿）、计算类型、联邦对象、runner 和参考开源实现。
- 5 档保护预设，可用性由计算类型、执行模式和 runner 能力判断。

### 界面

- 配置步骤所有维度和候选项始终展开；上游选完后下游不支持的选项自动置灰（不显示原因）；唯一可选项自动选中；不显示成熟度、前沿或参考实现标注。
- 场景是维度 1，子项 1.1–1.6 在同一张卡片里、各自成卡：可直接选场景（按"模型训练 / 分析与评估 / 知识协作"分组），也可逐个子项选择；场景确定后子项只能在场景内调整且不能取消。
- 已选选项再点一次即取消；再点一次当前场景即取消场景。
- 右侧"平台推导"面板实时显示场景、执行模式、联邦对象、计算类型、runner 和保护机制。
- 输入与参与方接入按接入方式变化，纵向显示 Guest / Host 角色，产物类场景可以上传文件（只记录文件名和大小）。
- 发布需要选择范围并手动确认，可以查看冻结的 FrontendRunPlan。
- 桌面端与移动端均可用。

### 工程质量

- React 19 + TypeScript 6 + Vite 8。
- 领域层（维度、选择引擎、计划推导、状态机、模拟器）与 React 组件分离，状态机不含场景分支。
- 旧 LoRA mock 执行模型已删除，不再作为其他场景的隐藏执行器。
- 测试：57 个，覆盖 6 个测试文件。
- `lint`、`typecheck`、`test` 和生产构建全部通过。

## 技术债务与风险

- 能力矩阵目前写在前端注册表里，后端阶段应改为由 runner manifest 声明，前端只展示。
- 参与方、指标和产物都是演示数据，界面和文档必须持续标明"模拟"。
- 保护配置容易被误解为已实现安全能力。
- 前沿场景（LoRA 聚合、FedRAG、Agent / Skill）工具链变化快，第一批后端 demo 优先选主流场景和一个 LoRA 场景。
- 截图目录包含多轮历史设计，正式汇报使用 `dimension-*.png`。

## 下一阶段建议

### M1：确认分层

- 用当前前端评审维度、场景和依赖规则是否合理，调整后再冻结。

### M2：两个后端 demo

- 选两个结构差异最大的场景验证抽象，候选：横向 LoRA 联邦微调（Flower，多轮联邦）和纵向 PSI + SecureBoost（FATE，纵向协议）。
- 每个 demo 打通真实输入 manifest、规则校验、本机隔离容器、执行、评测和产物登记。

### M3：平台化

- 定义 `RunSpec`、`InputManifest`、`PreflightReport`、`RunnerManifest` 的 JSON Schema，把前端注册表拆成版本化配置。
- 增加 API、PostgreSQL、对象存储、队列、身份和审计。

### M4：Agent 与安全能力

- Agent 解释结构化规则，并处理受控长尾问题。
- 按场景逐项落地 SecAgg、DP、HE / MPC 或 TEE。
