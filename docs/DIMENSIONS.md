# 配置维度设计

最后复核：2026-09-28（T27 改为云服务下单式的 7 个维度；纵向改用隐语 SecretFlow）

平台把主流联邦方法的共同特征整理成 7 个维度，按云服务下单的顺序一步步选择：先选协作场景，平台给出其余每一项的推荐值，用户只改关心的部分，确认后创建项目。代码实现见 `app/src/domain/taxonomy.ts`（场景、算力、数据类型、模型）、`app/src/domain/dimensions.ts`（7 个维度及子项）和 `app/src/domain/selection.ts`（校验规则）。

> 本文用"维度 1–7"和"子项 2.1、3.2……"称呼这些选择，不用 `L`，因为 `L` 在 [ARCHITECTURE.md](./ARCHITECTURE.md) 里表示架构层。

## 收录原则（demo 阶段）

1. **看现在大家在用什么**，而不是框架是否还在发版：方法本身主流就收录，再找仍在维护的实现来执行。FATE 自 2024 年 7 月后没有新版本，新项目多转向隐语，所以 SecureBoost、纵向逻辑回归保留，由隐语 SecretFlow 执行。
2. **只保留最通用、最主流的**：同类方法只留最常用的一两个；大模型 / Agent 相关方法例外保留。
3. **能拆就拆**：即使某个方法在框架里是打包好的一整套协议（例如纵向 SecureBoost），也按 7 个维度拆开；协议内固定的部分显示为锁定值，真正能选的部分（隐私求交协议、同态加密方案、树数量）开放出来。
4. **安全机制只列框架实际提供的**，不做"数学上可行"的抽象组合。
5. **用业内通用的专业名词**，每个选项附一句说明；界面不显示成熟度或"前沿"标注。

## 设计原则

1. **像云服务下单**：7 个维度从上到下排列，右侧是订单摘要（配置清单、平台推导、资源与耗时预估），确认后创建项目，配置随即锁定。
2. **先选场景，其余自动给推荐值**：选完场景就是一份完整、可运行的配置。
3. **只有前面的约束后面的**：上游改选后，失效的下游回到推荐值。
4. **子项三种状态**：不适用的不显示；由场景固定的显示为锁定值（标"固定"）；可选的展开全部候选，与前面冲突的置灰。
5. **每个子项都必须有值**：已选选项再点一次不会取消，可选能力用"关闭"表示；再点一次当前场景即取消场景。
6. **资源在方法之前**：维度 2 的算力规格约束维度 3、4 的可选项，例如显存不够时大模型置灰。
7. **平台能推导的不让用户选**：执行框架、执行模式、交换对象、资源与耗时预估显示在订单摘要里。

## 7 个维度

```text
维度 1 协作场景        横向联邦训练 / 纵向联邦训练 / 联邦统计分析 / Agent 记忆联邦
维度 2 参与方与算力     参与方数量、部署位置、节点算力规格（每方最低）、网络
维度 3 数据            接入方式、数据类型、样本对齐
维度 4 模型            模型（或分析类型）、参数共享方式
维度 5 算法与训练       聚合算法、轮次、每轮参与比例、每轮本地训练
维度 6 安全与隐私       基础安全、安全聚合、差分隐私、加密计算、输出保护
维度 7 评测与交付       评测方式、交付物、交付范围
```

### 维度 1：协作场景

| 场景 | 分组 | 执行框架（推导） | 执行模式 |
|---|---|---|---|
| 横向联邦训练 | 连接节点 · 多轮运行 | Flower | 多轮联邦 |
| 纵向联邦训练 | 连接节点 · 多轮运行 | 隐语 SecretFlow | 纵向协议 |
| 联邦统计分析 | 上传文件 · 一次完成 | 平台统计服务 | 单轮汇总 |
| Agent 记忆联邦 | 上传文件 · 一次完成 | 平台记忆合并服务 | 单轮合并 |

### 维度 2：参与方与算力

| 子项 | 候选 | 适用 | 默认 |
|---|---|---|---|
| 2.1 参与方数量 | 2 方 / 3–5 方 / 6–10 方（决定开始运行所需的最少确认方数：2 / 3 / 6） | 全部 | 纵向 2 方，其余 3–5 方 |
| 2.2 部署位置 | 阿里云 / 腾讯云 / 华为云 / AWS / Azure / 私有机房 | 节点类 | 阿里云 |
| | 平台托管（锁定） | 文件类 | — |
| 2.3 节点算力规格（每方最低） | 通用 CPU（8 vCPU · 32 GB）/ 计算型 CPU（32 vCPU · 128 GB）/ GPU 16 GB（T4 级）/ GPU 24 GB（A10、L4 级）/ GPU 80 GB（A100、H100 级） | 节点类 | 横向 GPU 24 GB，纵向计算型 CPU |
| 2.4 网络 | 公网（TLS）/ 专线 | 节点类 | 纵向专线，横向公网 |

部署位置指本机构节点：公有云由平台在授权的云账号中创建实例，私有机房提供一条命令的安装包。其他参与方加入时各自选择节点，节点必须不低于 2.3 的规格。

### 维度 3：数据

| 子项 | 候选 | 适用 |
|---|---|---|
| 3.1 数据接入方式 | 节点本地（锁定）/ 文件上传（锁定） | 节点类 / 文件类 |
| 3.2 数据类型 | 图像 / 结构化表格 / 文本指令（JSONL，需要 GPU） | 横向 |
| | 结构化表格（含对齐主键）/ 分组汇总表 / Agent 记忆（均锁定） | 纵向 / 统计 / 记忆 |
| 3.3 样本对齐 | ECDH-PSI（通信量低，百万级以内）/ RR22-PSI（计算快，千万级以上） | 纵向 |
| | 结构一致性校验（锁定） | 其他 |

### 维度 4：模型

| 数据类型 | 候选 | 算力要求 |
|---|---|---|
| 图像 | ResNet-18 | CPU 可运行，建议 GPU |
| 结构化表格 | MLP / XGBoost / 逻辑回归 | CPU |
| 文本指令 | Qwen2.5-1.5B-Instruct / Qwen3-1.7B / Llama-3.2-3B-Instruct | GPU ≥16 GB |
| 纵向特征表 | SecureBoost（建议 ≥16 vCPU）/ 纵向逻辑回归（SS-LR） | CPU |
| 分组汇总表 | 基础统计量 / 分布与分位数 | 平台托管 |
| Agent 记忆 | Agent 记忆条目（锁定） | 平台托管 |

4.2 参数共享方式：大模型为 LoRA / QLoRA（Llama-3.2-3B 的 LoRA 需要 24 GB，QLoRA 16 GB）；其他横向模型为全量参数或树集成（锁定）；纵向为分片持有（锁定）。

### 维度 5：算法与训练

| 子项 | 候选 | 适用 |
|---|---|---|
| 5.1 聚合算法 | FedAvg / FedProx / FedAdam | 横向神经网络、线性模型、大模型 |
| | XGBoost Bagging（锁定） | 横向 XGBoost |
| | SecureBoost 协议 / SS-LR 协议（锁定，随模型） | 纵向 |
| | 求和聚合 / 去重与冲突仲裁（锁定） | 统计 / 记忆 |
| 5.2 轮次 | 训练轮次 10 / 20 / 50；树数量 50 / 100 / 200；迭代次数 20 / 50 / 100；单轮（锁定） | 横向 / SecureBoost / SS-LR / 文件类 |
| 5.3 每轮参与比例 | 全部参与方 / 每轮抽样 50%（2 方时不可选） | 横向 |
| 5.4 每轮本地训练 | 1 / 2 / 5 个 epoch（XGBoost 为每轮新增 1 / 2 / 5 棵树） | 横向 |

### 维度 6：安全与隐私

| 子项 | 候选 | 适用 | 依据 |
|---|---|---|---|
| 6.1 基础安全 | mTLS · 隔离沙箱 · 审计日志（锁定） | 全部 | 平台基础能力 |
| 6.2 安全聚合 | 关闭 / SecAgg+（需 ≥3 方，XGBoost 不可用） | 横向 | Flower SecAgg+ 工作流 |
| 6.3 差分隐私 | 关闭 / ε = 8 / ε = 3 / ε = 1（XGBoost 不可用） | 横向、统计 | Flower 中心化 DP 包装；统计结果加噪 |
| 6.4 加密计算 | OU / Paillier 同态加密（SecureBoost）；秘密分享 SPU（SS-LR，锁定） | 纵向 | 隐语 SGB 支持切换 Paillier / OU，OU 约快 3–4 倍 |
| 6.5 输出保护 | 最小分组阈值 5 / 10 / 20 条 | 统计 | 小分组抑制 |
| | 敏感信息脱敏（锁定） | 记忆 | 记忆是明文内容 |

### 维度 7：评测与交付

| 子项 | 候选 | 适用 |
|---|---|---|
| 7.1 评测方式 | 各方本地验证 / 平台独立测试集 / 与单方基线对比 | 横向 |
| | 标签方验证 / 与标签方单方模型对比 | 纵向 |
| | 一致性校验 / 沙箱任务回放（锁定） | 统计 / 记忆 |
| 7.2 交付物 | LoRA Adapter / 全局 XGBoost 模型 / 全局模型权重 / 分片联合模型 / 统计报告 / 合并后的记忆文件（锁定，由模型推导） | 全部 |
| 7.3 交付范围 | 仅发起方 / 全部参与方 / 指定参与方（交付时勾选） | 全部 |

## 主要约束

| 前面的选择 | 影响 |
|---|---|
| 2.3 CPU 规格 | 3.2 文本指令置灰（大模型需要 GPU） |
| 2.3 GPU 16 GB | Llama-3.2-3B 只能用 QLoRA |
| 2.3 通用 CPU（纵向） | SecureBoost 置灰，改用 SS-LR（加密计算随之锁定为秘密分享） |
| 2.1 两方 | SecAgg+、50% 抽样置灰 |
| 4.1 XGBoost | 聚合锁定为 Bagging；SecAgg+、差分隐私置灰 |
| 3.2 数据类型 | 4.1 只列这类数据对应的模型 |

## 平台推导项（订单摘要）

| 推导项 | 来源 |
|---|---|
| 执行框架、执行模式 | 场景 |
| 交换对象、计算类型、交付物 | 模型（LoRA 时为 LoRA 增量） |
| 执行位置（控制面 / 协调方 / 参与方侧 / 评测） | 执行模式 |
| 安全机制清单 | 维度 3 对齐 + 维度 6 |
| 资源、耗时、消耗（GPU·时 / CPU 节点·时） | 算力规格、模型、轮次、本地训练、抽样、安全聚合、QLoRA |
| 注意事项 | 差分隐私与参与方数量、ε = 1、纵向走公网、QLoRA 精度 |

以上内容一起构成 `FrontendRunPlan`（`app/src/domain/plan.ts`，`frontend.run-plan/v2`），是后端 RunSpec 的前身。

## 用真实方法检验

| 真实方法或案例 | 落点 |
|---|---|
| FlowerTune 大模型联邦微调 | 横向 · GPU 24 GB · 文本指令 · Qwen2.5-1.5B · LoRA · FedAvg |
| 跨医院影像分类 | 横向 · 图像 · ResNet-18 · FedProx，可选 SecAgg+ / DP |
| 横向联邦 XGBoost | 横向 · 结构化表格 · XGBoost · Bagging |
| 银行 + 电商风控 | 纵向 · 计算型 CPU · SecureBoost · ECDH-PSI · OU |
| 可解释的纵向信用评分 | 纵向 · SS-LR · 秘密分享 |
| 多省新增人口、老龄人口统计 | 统计 · 基础统计量 · 最小分组阈值 10 |
| 跨团队共享 Agent 经验（Agent KB） | 记忆 · 去重与冲突仲裁 · 敏感信息脱敏 |

## 未收录

| 类别 | 内容 | 原因 |
|---|---|---|
| 框架 | FATE（T27） | 2024 年 7 月后不再发版；方法保留，由隐语执行 |
| 框架 | NVFlare 作为纵向框架（T27） | 国内纵向联邦以隐语为主；NVFlare 可作为 Flower 应用的生产运行环境 |
| 安全 | KKRT-PSI（T27） | 隐语 PSI v2 以 ECDH、RR22 为主，RR22 比 KKRT 更快 |
| 安全 | CKKS、TEE、鲁棒聚合（T17、T26） | 保留的方法里没有实现，或生产中很少启用 |
| 算力 | 多卡规格（T27） | 3B 以内的 LoRA 单卡即可 |
| 场景 | 联邦评估、联邦检索、LoRA 微调独立场景（T26） | 见 D19 |
| 其他 | 个性化联邦、拆分学习、本地差分隐私、MPC 版 XGBoost、去中心化 / 异步联邦 | 小众或暂不纳入 |
