# 配置维度设计

最后复核：2026-09-24（T24 按最通用主流精简，安全维度按框架实际能力重做）

平台不追求覆盖所有联邦方法，但对方法有一套统一分层：共 3 个维度。第一步先选场景（维度 1），它下面的 5 个子项（1.1–1.5）描述这个场景的具体条件，选完场景后自动填好、可在场景内调整；维度 2 选协作策略，维度 3 看安全与隐私。代码实现见 `app/src/domain/taxonomy.ts`（候选项）和 `app/src/domain/selection.ts`（依赖规则）。

> 本文用"维度 1–3"和"子项 1.1–1.5"称呼这些问题，不用 `L`，因为 `L` 在 [ARCHITECTURE.md](./ARCHITECTURE.md) 里表示架构层。

## 收录原则（demo 阶段）

1. **只保留最通用、最主流的方法**：有成熟开源实现、在真实项目里被广泛使用。
2. **不追求全覆盖，也不做太细**：小众方法即使论文和 benchmark 很成熟也不收录；同类方法只留最常用的一两个。
3. **Agent / 大模型相关的方法例外保留**，即使还在快速演进。
4. **安全机制只列框架实际提供的**，不做"数学上可行"的抽象组合。
5. 界面不显示成熟度或"前沿"标注；注册表内部把大模型 / Agent 相关条目标为 `frontier`，只用于文档和运行计划记录。
6. 参与方形态只支持跨机构（Cross-silo）。端侧联邦需要 Google、Apple 那样的基础设施，不在 demo 范围内，所以不作为子项。

## 设计原则

1. **按用户最先能回答的问题排序**：先选场景，再看场景条件，最后选算法和安全增强。
2. **只有前层约束后层**：回退改了前面的选择时，后面失效的选项清空。
3. **所有维度和候选项始终展开**，不折叠。上游选完后，下游不支持的选项自动置灰，不显示原因文字；上游还没选时，下游选项也是灰的。不适用的维度整组置灰。
4. **只剩一个可选项时自动选中**，界面标注"自动选中"。
5. **第一步先选场景（维度 1）**。场景和其他维度用同样的选项卡片展示，按"模型训练 / 分析与评估 / 知识协作"分组。子项 1.1–1.5 在同一张卡片里、各自是独立的圆角卡片；没选场景时子项全部置灰，选完场景后自动填好。
6. **子项只能在场景内调整**：会让路径离开当前场景的选项置灰，且子项不能取消。换场景直接点另一个场景；再点一次当前场景即取消场景。标题里不重复编号，编号只显示在左侧圆圈中。
7. **已选选项再点一次即取消**，依赖它的下游一起清空（子项除外）。
8. **平台能推导的不让用户选**：联邦对象、计算类型、执行模式、输入接入方式、runner、评测、输出由平台推导，显示在 Run Plan 里。
9. **不支持的原因保留在规则引擎里**，用于准入检查和测试，不在配置页展示。

## 选择顺序与依赖

```text
维度 1 场景                第一步先选；选完后子项自动填好
  1.1 协作目标             想共同完成什么
  1.2 各方投入             每个参与方拿出来的是什么
  1.3 数据关系             横向 / 纵向（仅本地数据时）
  1.4 模型类别             神经网络 / 树 / 线性（仅训练时）
  1.5 共享方式             全量共享 / LoRA（仅横向训练时）
  ═══► 子项只能在所选场景内调整
维度 2 协作策略            → 推导联邦对象、计算类型、执行模式、runner
维度 3 安全与隐私          内置保护自动生效 + 可选增强（只列 runner 实际提供的，可多选）
运行默认值                基础模型、轮次等都有默认值，不在界面展示
```

流程中配置（不在配置页）：数据接入（按选择匹配已登记的联邦数据，或上传自己的数据由 Agent 检查）、执行预设与运行环境、评测闸门、发布范围。

| 场景 | 分组 | 子项路径 | 执行模式 |
|---|---|---|---|
| 模型联合训练 | 模型训练 | 训练 / 本地数据 / 横向 / 任意类别 / 全量共享 | 多轮联邦 |
| LoRA / Adapter 联邦微调 | 模型训练 | 训练 / 本地数据 / 横向 / 神经网络 / LoRA | 多轮联邦 |
| 纵向联合建模 | 模型训练 | 训练 / 本地数据 / 纵向 / 树或线性 | 纵向协议 |
| 联邦评估 | 分析与评估 | 评估 / 本地测试数据 | 纯评测 |
| 联邦统计分析 | 分析与评估 | 统计 / 本地数据 / 横向 | 单轮聚合 |

## 维度 3：安全与隐私

分两部分：**内置保护**随策略自动生效，只展示；**可选增强**只列该策略所在 runner 实际提供的，可以多选，不选就只有内置保护。

| 策略 | 内置保护 | 可选增强 | 依据 |
|---|---|---|---|
| 所有策略 | mTLS、隔离沙箱、审计日志 | — | 平台基础能力 |
| FedAvg、FedProx、LoRA FedAvg | — | 安全聚合 SecAgg+、差分隐私（可同时选） | Flower 内置 SecAgg+ 工作流和中心化 DP 包装器，官方示例同时使用两者 |
| XGBoost 直方图聚合 | — | 同态加密 CKKS | NVFlare 安全 XGBoost 用 CKKS 加密横向梯度直方图 |
| Hetero LR、SecureBoost | Paillier 同态加密、ECDH PSI | — | FATE 纵向协议自带加密；FATE 2.0 的 PSI 使用 ECDH |
| 本地评估 + 指标聚合 | 只回传聚合指标 | — | — |
| 联邦统计 | 最小计数阈值、统计值加噪（直方图另有分箱数上限） | — | NVFlare 联邦统计的隐私清洗 |
| FedRAG（RRF、集中重排） | — | 可信执行 TEE | Flower Labs 的机密 FedRAG 把融合和生成放进经过证明的 TEE |
| Agent / Skill 协作 | — | — | 目前没有公认的标准做法 |

选中的增强如有注意事项（例如差分隐私在参与方少时影响精度、同态加密增加耗时、TEE 需要硬件），会在准入检查中提示。SecAgg+ 在参与方少于 3 个时，准入会给出提示。

## 运行默认值（不在界面展示）

例如 LoRA 的基础模型、rank、轮次；纵向的 PSI、迭代次数。这些都有默认值、不是必须由用户选择的项，只在 FrontendRunPlan 中记录，供模拟执行使用。

## 平台推导项

| 推导项 | 来源 |
|---|---|
| 联邦对象、计算类型、runner | 策略 |
| 执行模式、输入接入方式、评测方案、输出 | 场景 |
| 执行位置（控制面 / 协调方 / 参与方侧 / 评测） | 执行模式 |
| 安全机制 | 内置保护 + 已选增强 |

以上内容一起构成 `FrontendRunPlan`（`app/src/domain/plan.ts`），是后端 RunSpec 的前身。

## 用真实方法检验

| 真实方法或案例 | 落点 |
|---|---|
| 跨医院影像分割（FedAvg / FedProx） | 模型联合训练 · 神经网络 · FedAvg，可选 SecAgg+ / DP |
| 横向联邦 XGBoost | 模型联合训练 · 树模型 · XGBoost 直方图聚合，可选 CKKS |
| 银行 + 电商风控（SecureBoost） | 纵向联合建模 · 树模型 · SecureBoost，内置 Paillier + ECDH PSI |
| FlowerTune LLM | LoRA 联邦微调 · FedAvg，可选 SecAgg+ / DP |
| 多站点统计 | 联邦统计分析，内置最小计数和加噪 |
| FedRAG | 联邦检索 · RRF，可选 TEE |

## 未收录

| 类别 | 内容 | 原因 |
|---|---|---|
| 场景 | 个性化联邦、异构模型协作（T17） | 主要在研究和 benchmark 中使用 |
| 场景 | 模型与 Adapter 聚合（T24） | 模型合并本身不是标准的联邦方法 |
| 子项 | 参与方形态：端侧设备、混合节点（T17、T24） | demo 只做跨机构 |
| 候选 | 联邦迁移（T17）；模型服务 Endpoint（T24） | 不够通用 |
| 策略 | SCAFFOLD、树 Bagging、Split NN、Task Arithmetic、LoRA 拼接、FedRAG 分数融合（T17）；FedAdam / FedYogi、LoRA FedProx、TIES、DARE、跨站点交叉验证、统一基准评测、PSI 交集统计（T24） | 同类方法只留最常用的 |
| 安全 | 抗恶意参与方鲁棒聚合（T17）；五档抽象保护预设（T24） | 生产中很少启用；改为按框架实际能力列出 |
| 其他 | 去中心化 / Swarm、异步联邦 | 暂不纳入 |
