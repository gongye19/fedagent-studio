# 配置维度设计

最后复核：2026-09-24（T14 批准，T15 实现，T16 调整展示方式，T17 精简候选，T18 去掉标注，T19 场景锁定）

平台不追求覆盖所有联邦方法，但对方法有一套统一分层：用户按顺序回答 8 个问题，逐层收窄，最后落到一个可运行的场景和策略。代码实现见 `app/src/domain/taxonomy.ts`（候选项）和 `app/src/domain/selection.ts`（依赖规则）。

> 本文用"维度 1–8"称呼这些问题，不用 `L`，因为 `L` 在 [ARCHITECTURE.md](./ARCHITECTURE.md) 里表示架构层。

## 收录原则

1. **只保留主流、实际用得多的方法**：有成熟开源实现、在真实项目里被广泛使用。
2. **小众方法不收录**：即使论文和 benchmark 很成熟，实际没什么人用，也不放进候选。
3. **大模型 / Agent 相关的方法可以保留**：即使还在快速演进。
4. 界面不显示任何成熟度或"前沿"标注。注册表内部仍把候选分为 `mainstream` / `frontier`，只用于本文档和 FrontendRunPlan 记录，下表"标注"列即此内部分类。

## 设计原则

1. **按用户最先能回答的问题排序**：先问目标，再问各方手里有什么、数据怎么分布、谁参与，最后才问算法和保护。
2. **只有前层约束后层**：后面的选择不会反过来让前面的选择失效。回退改了前面的选择时，后面失效的选项清空。
3. **所有维度和候选项始终展开**，不折叠。上游选完后，下游不支持的选项自动置灰，不显示原因文字；上游还没选时，下游选项也是灰的。不适用的维度（例如检索问答的数据关系）整组置灰。
4. **只剩一个可选项时自动选中**，界面标注"自动选中"。
5. **不支持的原因保留在规则引擎里**，用于准入检查和测试，不在配置页展示。
6. **维度 1–5 就是在定位场景**，和场景选择放在同一张卡片里。卡片顶部可以直接选场景，维度 1–5 自动填好（场景内有多个选项的维度用默认值）；也可以逐个维度往下选，选到能确定场景时自动锁定该场景。
7. **场景一旦确定，维度 1–5 只能在场景内调整**：会让路径离开当前场景的选项置灰，保留下来能点的都仍属于该场景（例如 LoRA 联邦微调里跨机构 / 端侧可以切换）。换场景只能在卡片顶部重新选择，或清空。
8. **平台能推导的不让用户选**：联邦对象、计算类型、执行模式、输入接入方式、runner、评测、输出由平台推导，显示在 Run Plan 里。
9. **注册表为每条策略记录参考开源实现**，作为分层的现实依据和 runner 推导来源；界面不展示"参考实现"，只在 Run Plan 显示推导出的 runner。

## 选择顺序与依赖

```text
维度 1 协作目标            想共同完成什么
  │ 过滤维度 2 的候选
维度 2 各方投入            每个参与方拿出来的是什么
  │ 只有"本地数据"进入维度 3
维度 3 数据关系            各方数据怎么分布
  │ 过滤维度 4、维度 5
维度 4 参与方形态          谁参与，规模和稳定性如何
  │ 只有"训练模型"进入维度 5
维度 5 模型形态            模型类别 + 共享方式（或已训练产物的类型）
  ═══► 匹配场景模板（维度 1–5 的组合唯一对应一个模板）
维度 6 协作策略            → 推导联邦对象、计算类型、执行模式、runner
维度 7 安全与信任          由"计算类型 × 执行模式 × 参与方形态 × runner 能力"过滤
维度 8 场景参数            只放策略没有隐含决定的可调项
```

流程中配置（不在第一屏）：输入与参与方接入（含角色）、执行预设与运行环境、评测闸门、发布范围。

## 维度 1：协作目标

| 候选 | 说明 | 标注 |
|---|---|---|
| 训练模型 | 共同得到一个或多个模型 | |
| 评估模型 | 在多方数据或基准上验证已有模型 | |
| 统计分析 | 联合计算统计量，不训练模型 | |
| 检索增强问答 | 跨多方知识库检索并回答 | 前沿 |
| Agent 与技能协作 | 共享轨迹、技能或 Agent 策略 | 前沿 |

## 维度 2：各方投入

统一"多轮训练"和"产物聚合"，不需要把产品拆成两个平台。它同时决定输入接入方式。

| 候选 | 可用目标 | 输入接入 |
|---|---|---|
| 本地数据（不出域） | 训练、统计 | 连接节点 + 数据契约 |
| 已训练的模型或 Adapter | 训练、Agent | 上传文件到隔离 staging |
| 本地测试数据 | 评估 | 连接评测节点 |
| 模型服务 Endpoint | 评估 | 注册 Endpoint |
| 文档与索引 | 检索 | 注册检索 Endpoint + 索引声明 |
| 轨迹与 Skill | Agent | 上传 Skill 包或轨迹包 |

## 维度 3：数据关系

仅在各方投入为"本地数据"时可选。

| 候选 | 定义 |
|---|---|
| 横向 | 字段相同，样本不同 |
| 纵向 | 样本重叠，字段不同，需要样本对齐 |

## 维度 4：参与方形态

| 候选 | 约束 |
|---|---|
| 跨机构 Cross-silo | 所有路径可用 |
| 端侧设备 Cross-device | 只用于横向数据上的训练和统计 |

"本地模拟"不是参与方形态，是执行预设里的运行环境。

## 维度 5：模型形态

仅在"训练模型"时可选。

- **模型类别**（本地数据）：神经网络 / 树模型 / 线性模型。纵向数据下神经网络不可选（Split NN 用得少，未收录）。
- **共享方式**（横向）：全量共享 / 参数高效 LoRA·Adapter（前沿）。PEFT 只适用于神经网络；树模型和线性模型只能全量共享，会被自动选中。
- **纵向**：不问共享方式，由模型类别直接决定策略（线性 → Hetero LR，树 → SecureBoost）。
- **已训练产物**：不问模型类别，改问产物类型：全量模型权重 / LoRA·Adapter。

## 场景模板（维度 1–5 的落点）

| 场景 | 路径 | 执行模式 | 标注 |
|---|---|---|---|
| 模型联合训练 | 训练 / 本地数据 / 横向 / 任意类别 / 全量共享 | 多轮联邦 | |
| LoRA / Adapter 联邦微调 | 训练 / 本地数据 / 横向 / 神经网络 / PEFT | 多轮联邦 | 前沿 |
| 模型与 Adapter 聚合 | 训练 / 已训练产物 / 权重或 Adapter | 产物处理 | 前沿 |
| 纵向联合建模 | 训练 / 本地数据 / 纵向 / 树或线性 | 纵向协议 | |
| 联邦评估 | 评估 / 本地测试数据或 Endpoint | 纯评测 | |
| 联邦统计分析 | 统计 / 本地数据 / 横向或纵向 | 单轮聚合（横向）或纵向协议（纵向） | |
| 联邦检索 FedRAG | 检索 / 文档与索引 | 查询时联邦 | 前沿 |
| Agent / Skill 协作 | Agent / 轨迹与 Skill 或 Agent Adapter | 产物处理 | 前沿 |

## 维度 6：协作策略

每条策略声明：标注、计算类型、联邦对象、runner、参考实现，以及需要的模型类别、数据关系或各方投入。

| 场景 | 候选 | 计算类型 | 参考实现 |
|---|---|---|---|
| 模型联合训练（神经网络 / 线性） | FedAvg、FedProx、FedAdam / FedYogi | 可加 | Flower、NVFlare |
| 模型联合训练（树） | 直方图聚合 XGBoost | 可加 | NVFlare、Flower |
| LoRA 联邦微调（前沿） | FedAvg、FedProx | 可加 | Flower FlowerTune、FATE-LLM |
| 模型与 Adapter 聚合（前沿） | 加权平均、TIES-Merging、DARE | 可加 / 比较 | mergekit |
| 纵向联合建模 | Hetero LR、SecureBoost | 纵向协议 | FATE |
| 联邦评估 | 本地评估 + 指标聚合、跨站点交叉验证（本地测试数据）；统一基准评测（Endpoint） | 可加 / 拼接 | Flower、NVFlare、lm-evaluation-harness |
| 联邦统计分析 | 计数 / 求和 / 均值方差、直方图 / 分位数（横向）；PSI 交集统计（纵向） | 可加 / 纵向协议 | NVFlare、FATE |
| FedRAG（前沿） | Reciprocal Rank Fusion、集中重排 | 比较 / 需理解内容 | Flower FedRAG 示例 |
| Agent / Skill 协作（前沿） | 去重合并、冲突仲裁、轨迹蒸馏（轨迹与 Skill）；Agent Adapter 聚合（已训练产物） | 需理解内容 / 可加 | 自定义 runner、mergekit |

共 23 条策略。

## 维度 7：安全与信任

选一档保护预设。可用性由能力矩阵判断，不用场景黑名单。

| 预设 | 机制 | 可用条件 |
|---|---|---|
| 基础保护 | mTLS、隔离沙箱、审计日志 | 纵向协议除外（纵向至少需要加密计算） |
| 隐藏单方更新 | SecAgg+、更新裁剪 | 计算类型为"可加"；参与方少于 3 个时准入给出提示 |
| 样本级隐私 | 差分隐私、SecAgg+、隐私预算记账 | 可加，且不是产物处理；当前纵向 runner 不提供 |
| 加密计算 | 同态加密、MPC、密钥服务 | 可加或纵向协议；提示耗时显著增加 |
| 可信执行 | TEE、远程证明、密封密钥 | 协调方需有 TEE 硬件；当前纵向 runner 不提供 |

## 维度 8：场景参数

只放策略没有隐含决定的可调项，例如 LoRA 的基础模型、rank、target modules、轮次；纵向的实体对齐键、PSI 算法。参数可以只对某些策略出现（例如 TIES / DARE 的保留比例）。换场景时参数回到新场景的默认值。

## 用真实方法检验

| 真实方法或案例 | 落点 |
|---|---|
| 跨医院影像分割（FedAvg / FedProx） | 训练 / 本地数据 / 横向 / 跨机构 / 神经网络 / 全量 → 模型联合训练 |
| 横向联邦 XGBoost | 同上但模型类别为树 → 自动选中直方图聚合 |
| 银行 + 电商风控（SecureBoost） | 训练 / 本地数据 / 纵向 / 跨机构 / 树 → 纵向联合建模，自动加密计算 |
| FlowerTune LLM | 训练 / 本地数据 / 横向 / 神经网络 / PEFT → LoRA 联邦微调 |
| 已训练 LoRA 用 TIES 合并 | 训练 / 已训练产物 / Adapter → 模型与 Adapter 聚合，SecAgg 不可用 |
| Gboard 类端侧训练（DP + SecAgg） | 训练 / 本地数据 / 横向 / 端侧 / 神经网络 / 全量 → 样本级隐私 |
| 多站点统计 | 统计 / 本地数据 / 横向 → 单轮聚合 |
| FedRAG | 检索 / 文档与索引 → 查询时联邦 |

## 未收录

按收录原则删除或暂不纳入（T17）：

| 类别 | 内容 | 原因 |
|---|---|---|
| 场景 | 个性化联邦（FedBN、Ditto、FedRep、Clustered FL） | 主要在研究和 benchmark 中使用 |
| 场景 | 异构模型协作（FedMD、FedProto、表征对齐） | 主要在研究中使用 |
| 策略 | SCAFFOLD、树 Bagging / Cyclic、Split NN、PEFT 场景的 FedAdam、Task Arithmetic、LoRA 拼接、FedRAG 分数融合 | 实际使用少，已有更常用的替代 |
| 候选项 | 混合节点、混合 / 联邦迁移 | 实际项目中很少作为独立形态出现 |
| 保护 | 抗恶意参与方（Krum / Median / Trimmed Mean） | 生产联邦里很少启用 |
| 其他 | 去中心化 / Swarm、异步联邦 | 暂不纳入 |
