# 配置维度设计

最后复核：2026-09-25（T26 场景按运行方式重分为 4 个，横向照 Flower、纵向改用 NVFlare）

平台不追求覆盖所有联邦方法，但对方法有一套统一分层：共 3 个维度。第一步先选场景（维度 1），场景按**运行方式**分两类；训练场景下有 2 个子项（1.1 模型类别、1.2 共享方式）；维度 2 选协作策略，维度 3 看安全与隐私。代码实现见 `app/src/domain/taxonomy.ts`（候选项）和 `app/src/domain/selection.ts`（依赖规则）。

> 本文用"维度 1–3"和"子项 1.1–1.2"称呼这些问题，不用 `L`，因为 `L` 在 [ARCHITECTURE.md](./ARCHITECTURE.md) 里表示架构层。

## 收录原则（demo 阶段）

1. **只保留最通用、最主流的方法**：有成熟开源实现、在真实项目里被广泛使用。
2. **不追求全覆盖，也不做太细**：同类方法只留最常用的一两个。
3. **Agent / 大模型相关的方法例外保留**，即使还在快速演进。
4. **安全机制只列框架实际提供的**，不做"数学上可行"的抽象组合。
5. **框架要在持续维护**：横向训练照 Flower 的方式做；纵向训练用 NVFlare。FATE 自 2024 年 7 月后没有新版本，不再采用。
6. **场景要在平台上真正做事**：只在各方本地完成、平台只收结果的（联邦评估），或本质上是另一场景的（联邦训练检索模型 = 横向联邦训练），不单列。
7. 界面不显示成熟度或"前沿"标注；注册表内部把大模型 / Agent 相关条目标为 `frontier`，只用于文档和运行计划记录。参与方只支持跨机构。

## 设计原则

1. **先选场景，再选场景内的条件，最后选算法和安全增强。**只有前层约束后层；改了前面的选择，后面失效的选项清空。
2. **场景按运行方式分组**："连接节点 · 多轮运行"和"上传文件 · 一次完成"。运行方式决定数据接入这一步是连接节点还是上传文件。
3. **所有候选项始终展开**，不折叠。下游不支持的选项自动置灰，不显示原因文字。选定场景后，维度 2 只列该场景的策略。
4. **只剩一个可选项时自动选中**，界面标注"自动选中"。
5. **子项只在训练场景出现**：未选场景时子项置灰；选了统计分析或记忆联邦这类不需要子项的场景时，子项不显示。子项必须保留一个选择，不能取消。
6. **已选选项再点一次即取消**（子项除外）；再点一次当前场景即取消场景。
7. **平台能推导的不让用户选**：联邦对象、计算类型、执行模式、接入方式、runner、评测、输出由平台推导，显示在 Run Plan 里。
8. **不支持的原因保留在规则引擎里**，用于准入检查和测试，不在配置页展示。

## 选择顺序与依赖

```text
维度 1 场景                第一步先选
  1.1 模型类别             神经网络 / 树 / 线性（只在横向联邦训练）
  1.2 共享方式             全量参数 / LoRA（只在横向联邦训练；LoRA 只适用于神经网络）
维度 2 协作策略            只列当前场景的策略 → 推导联邦对象、计算类型、runner
维度 3 安全与隐私          内置保护自动生效 + 可选增强（只列 runner 实际提供的，可多选）
运行默认值                轮次、树数量等都有默认值，不在界面展示
```

流程中配置（不在配置页）：数据接入（节点类场景勾选已连接的节点、连接我方节点；文件类场景勾选其他参与方已提交的文件、上传我方文件由 Agent 检查）、执行预设与运行环境、评测闸门、发布范围。

## 维度 1：场景

| 场景 | 运行方式 | 各方做什么 | 平台做什么 | 执行模式 | 框架 |
|---|---|---|---|---|---|
| 横向联邦训练 | 连接节点 · 多轮 | 启动 Flower SuperNode，本地训练 | SuperLink 调度每一轮，ServerApp 按策略合并 | 多轮联邦 | Flower |
| 纵向联邦训练 | 连接节点 · 逐步交换 | 启动 NVFlare 客户端；标签方加密梯度，特征方在密文上算分裂统计 | 协调隐私求交和训练步骤 | 纵向协议 | NVFlare |
| 联邦统计分析 | 上传文件 · 一次 | 按模板上传本地汇总的统计表（计数、求和） | 由计数和求和重新计算整体比例、均值、方差；人数过少的分组不公布 | 单轮汇总 | 平台统计服务 |
| Agent 记忆联邦 | 上传文件 · 一次 | 上传 Agent 记忆文件（JSONL） | 脱敏、去重、处理冲突、沙箱回放验证，生成新的记忆文件供下载 | 单轮合并 | 平台记忆合并器 |

横向为什么有"全量 / LoRA"而纵向没有：横向每家都持有同一个完整模型，每轮交换的就是模型本身，所以可以选交换整套参数还是只交换 LoRA；纵向每家只持有模型的一部分，交换的是每一步的加密中间结果，没有"整个模型"可交换。纵向的主流模型是树模型，本身没有 LoRA。

纵向单独成为场景，是因为数据关系改变了整个流程：要先隐私求交对齐样本、通常只有一方有标签、几乎每一步都要交换加密中间结果、训完的模型按参与方分片保存（预测时也要各方一起算）、需要不同的框架。

### 子项（只在横向联邦训练）

| 子项 | 候选 |
|---|---|
| 1.1 模型类别 | 神经网络、树模型、线性模型 |
| 1.2 共享方式 | 全量参数、LoRA（只适用于神经网络） |

## 维度 2：协作策略

| 场景 | 候选 | runner |
|---|---|---|
| 横向联邦训练（神经网络 / 线性） | FedAvg、FedProx | Flower |
| 横向联邦训练（树） | XGBoost Bagging（Flower FedXgbBagging） | Flower |
| 纵向联邦训练 | 安全纵向 XGBoost | NVFlare |
| 联邦统计分析 | 计数 / 求和 / 均值方差、分布直方图 / 分位数 | 平台统计服务 |
| Agent 记忆联邦 | 去重合并、去重 + 冲突仲裁 | 平台记忆合并器 |

共 7 条策略。共享方式选 LoRA 时，FedAvg / FedProx 交换的是 LoRA 增量。

## 维度 3：安全与隐私

分两部分：**内置保护**随策略自动生效，只展示；**可选增强**只列该策略所在 runner 实际提供的，可以多选，不选就只有内置保护。

| 策略 | 内置保护 | 可选增强 | 依据 |
|---|---|---|---|
| 所有策略 | mTLS、隔离沙箱、审计日志 | — | 平台基础能力 |
| FedAvg、FedProx（含 LoRA） | — | 安全聚合 SecAgg+、差分隐私（可同时选） | Flower 内置 SecAgg+ 工作流和中心化 DP 包装器 |
| XGBoost Bagging | — | — | 交换的是树结构，SecAgg / DP 不适用 |
| 安全纵向 XGBoost | ECDH PSI、Paillier 同态加密 | — | NVFlare 安全 XGBoost 的纵向模式 |
| 联邦统计 | 最小分组阈值（直方图另有统一分箱） | 差分隐私（统计结果加噪） | 小分组抑制和加噪是联邦统计的常规做法 |
| Agent 记忆联邦 | 敏感信息脱敏 | — | 记忆是明文内容，上传后先脱敏 |

选中的增强如有注意事项（例如差分隐私在参与方或记录少时影响结果），会在准入检查中提示。SecAgg+ 在参与方少于 3 个时，准入会给出提示。

## 运行默认值（不在界面展示）

横向训练的轮次（20 轮）、每轮本地训练（1 epoch）；纵向训练的树数量（50 棵）。只在 FrontendRunPlan 中记录，供模拟执行使用。执行预设"快速验证"把轮次压到 3 轮。

## 平台推导项

| 推导项 | 来源 |
|---|---|
| 联邦对象、计算类型、runner | 策略（LoRA 时联邦对象为 LoRA 增量） |
| 执行模式、接入方式、评测方案、输出 | 场景（输出随共享方式变化：全局模型 / 全局 LoRA） |
| 执行位置（控制面 / 协调方 / 参与方侧 / 评测） | 执行模式 |
| 安全机制 | 内置保护 + 已选增强 |

以上内容一起构成 `FrontendRunPlan`（`app/src/domain/plan.ts`），是后端 RunSpec 的前身。

## 用真实方法检验

| 真实方法或案例 | 落点 |
|---|---|
| 跨医院影像分类（FedAvg / FedProx） | 横向联邦训练 · 神经网络 · 全量 · FedAvg，可选 SecAgg+ / DP |
| FlowerTune LLM | 横向联邦训练 · 神经网络 · LoRA · FedAvg |
| 横向联邦 XGBoost | 横向联邦训练 · 树模型 · XGBoost Bagging |
| 银行 + 电商风控 | 纵向联邦训练 · 安全纵向 XGBoost，内置 PSI + Paillier |
| 多省新增人口、老龄人口统计 | 联邦统计分析 · 计数 / 求和，内置最小分组阈值 |
| 跨团队共享 Agent 经验（Agent KB） | Agent 记忆联邦 · 去重 + 冲突仲裁 |

## 未收录

| 类别 | 内容 | 原因 |
|---|---|---|
| 场景 | 联邦评估（T26） | 评测在各方本地完成，平台只收分数；作为每次运行的"评测"步骤保留 |
| 场景 | 联邦检索 FedRAG（T26） | 属于在线问答服务，不是一次任务；"联邦训练检索模型"本质是横向联邦训练 |
| 场景 | LoRA 联邦微调独立场景（T26） | 与横向训练流程相同，并入为"共享方式 = LoRA" |
| 场景 | Agent / Skill 协作、Agent Adapter 聚合（T26） | 改为 Agent 记忆联邦 |
| 场景 | 个性化联邦、异构模型协作（T17）；模型与 Adapter 聚合（T24） | 主要在研究中使用；一次性模型合并不是标准联邦方法 |
| 子项 | 协作目标、各方投入、数据关系（T26） | 场景一选就确定，不需要再单独选 |
| 策略 | 纵向逻辑回归（T26） | NVFlare 没有内置实现，FATE 已停止更新 |
| 策略 | SCAFFOLD、Split NN、Task Arithmetic 等（T17、T24） | 同类方法只留最常用的 |
| 安全 | CKKS 同态加密、TEE（T26） | 保留的策略里没有 runner 提供 |
| 其他 | 去中心化 / Swarm、异步联邦 | 暂不纳入 |
