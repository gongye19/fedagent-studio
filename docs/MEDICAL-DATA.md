# 医疗病例接入

2026-10-13，T75。医疗诊断任务类型由 fedagent-evomedclaw 包注册，数据规范版本 1.0；EvoMedClaw 使用横向场景。

## 用户操作

在“参与方与数据”选择一个平台托管参与方，新增数据集，选择“横向联邦／医疗诊断”。可以下载空结构模板，也可以直接选择 MedAgentSim 的文本 OSCE JSONL。选择文件后检查编码与大小，再由后端的任务类型规则检查；显示总量、标注数量以及行号／字段问题。保存时再次检查，失败不部分创建参与方或数据集。网络失败可重试校验，格式问题可改文件后重新选择。

参与方本地只登记数据描述：下载模板准备本地文件，安装平台提供的客户端、SDK 与医疗插件，用详情里的命令连接。客户端按服务器下发的任务类型与规范版本检查文件、上报标注数量和已安装算法版本，原始病例不上传。当前支持平台托管和本地客户端，已有 Agent 服务的直接连接仍待适配。

## 规范

规范 JSONL 每行一病例，字段如下：

| 字段 | 内容 |
|---|---|
| id | 不重复的病例编号 |
| patient | 病人背景／主诉／病史，文本或对象 |
| objective | 医生的诊断任务目标 |
| examination | 可选查体，文本或对象 |
| tests | 可选检查结果，文本或对象；应用表单中的此字段使用 JSON 对象 |
| answer | 参考诊断，经验生成病例必需，评测／应用试用可选；明确别名可用 `|` 分隔 |
| split | learn（经验生成）或 eval（独立评测）；指定时每行都需要指定 |

不指定 split 时，按文件顺序留出末尾向上取整的 20% 为 eval，其余为 learn。至少两条病例且两个分组都存在；检查会拒绝两个分组之间完全重复的临床输入。试跑优先取一条 learn 和一条 eval，其余保持原顺序，因此每方最少两条。生产研究应由用户按实际病例对象预先划分 learn／eval；自动留出仅是默认的数据准备规则，不保证病例分布具有代表性。

接受的上游结构为 OSCE_Examination 下 Patient_Actor、Objective_for_Doctor、Physical_Examination_Findings、Test_Results、Correct_Diagnosis。无编号时按原文件行号生成编号。转换后参考诊断移到独立的 answer；诊断步骤剥离顶层及结构化内容中的保留标注字段，只在本地经验验证／判分时使用参考诊断。不要把参考诊断写进自然语言病史。

保存不可变的规范化 JSONL 及其内容哈希，并记录原始上传 SHA-256、规范版本；任务冻结这些信息。旧数学数据兼容规范 1.0，无法追溯的旧原始上传哈希保留为空，不虚构来源。规范版本不兼容时不能发起任务。

## 结果与应用

平台指标名为“诊断匹配率”：匹配完整诊断名称，忽略大小写、标点与协议前缀，按明确别名匹配；未标注评测病例不进入分母。只统计 eval，eval 轨迹不参与经验提炼。上游启发式 heldout_lift 等字段不作为平台效果指标，也不随全局产出导出。

应用试用填写病人信息、诊断目标，按需填写查体、检查结果与参考诊断；参考诊断只参与判分。`POST /v1/apps/{id}/apply` 保留带／不带成果对比；实际集成使用 `POST /v1/apps/{id}/invoke`，只运行带成果的一侧。数学输入仍为字符串，医疗输入为包含上述临床字段的对象。导出／复制使用算法的真实 JSON 格式，包含过程卡与可回用的记忆条目。

横向文本运行路径与适配限制见 [EVOMEDCLAW.md](./EVOMEDCLAW.md)。本地浏览器回归工具为 `tools/ui-check/medical-flow.mjs`，其假模型验证不用于证明算法效果。
