## G：产品目标

Federation Studio 是面向多种隐私协作任务的场景配置与运行控制台，而不是重新实现所有联邦算法。

机构用户像订阅云服务一样，按 7 个维度一步步选好联邦协作的配置，创建项目后邀请合作机构（或加入本机构的其他节点）组队；各方确认方案后，平台检查参与方与数据，生成执行计划，在隔离环境中调用适配的 runner，最后完成评测和交付。

平台负责：

1. 找出主流联邦方法（以及大模型 / Agent 相关方法）的共同特征，整理成统一的 7 个维度，让用户一步步选到可运行的配置，而不是暴露无约束的选项组合。
2. 判断参与方的数据、模型或知识产物是否满足方法契约。
3. 生成不可变的运行计划（前端为 FrontendRunPlan，后端为 RunSpec），在隔离的容器或沙箱中调用合适的执行后端。
4. 跟踪运行、评测结果和产物谱系，保留可审计记录。
5. 由 Agent 解释不兼容原因、给出修复建议，并处理硬规则之外的长尾问题。

平台统一的是配置、准入、编排、隔离、评测和追踪；具体算法由 Flower（横向训练）、隐语 SecretFlow（纵向训练）或平台自带的 runner（统计汇总、记忆合并）提供，参考已有实现，不重复造轮子。不同任务的差别落在"执行模式 + runner adapter"上。

## 配置模型

完整定义见 [DIMENSIONS.md](./DIMENSIONS.md)。按云服务下单的顺序排列：

1. **协作场景**：横向联邦训练、纵向联邦训练（连接节点 · 多轮运行）；联邦统计分析、Agent 记忆联邦（上传文件 · 一次完成）。
2. **参与方与算力**：参与方数量、部署位置、节点算力规格（每方最低）、网络。
3. **数据**：接入方式、数据类型、样本对齐。
4. **模型**：模型或分析类型、参数共享方式（LoRA / QLoRA 等）。
5. **算法与训练**：聚合算法、轮次、每轮参与比例、每轮本地训练。
6. **安全与隐私**：基础安全、安全聚合、差分隐私、加密计算、输出保护。
7. **评测与交付**：评测方式、交付物、交付范围。

选完场景即得到一份按推荐值填好的完整配置；执行框架、执行模式、交换对象、资源与耗时预估由平台推导。demo 阶段只收录最通用、最主流的方法，大模型 / Agent 相关方法例外保留。

## 使用方式

- **发起 + 邀请（跨机构）**：发起方配置并创建项目，邀请合作机构；对方接受、绑定节点、授权数据并确认方案。
- **组织内部联邦**：同一机构的多个节点或多份文件各作为一方。
- 配置只由发起方决定，其他方确认或拒绝；平台不向项目之外展示任何机构的数据。

## 当前阶段目标

当前里程碑是验证维度分层、组队方式和产品流程，而不是交付生产联邦系统：

- 前端完整表达 7 个维度及其依赖关系，4 个场景都能直接选择并跑通模拟流程。
- 工作台、新建项目、项目详情、邀请详情四个页面串起发起、邀请、组队、运行和交付。
- 明确区分已实现、前端模拟和未实现能力。
- 之后选两个运行方式不同的例子实现后端 demo：一个连接节点（横向联邦训练，Flower），一个上传文件（统计分析或记忆联邦）。

## 当前不承诺的能力

- 页面中的 SecAgg+、差分隐私、隐私求交、同态加密和秘密分享是保护配置，不代表协议已经实现。
- 页面中的 Flower、隐语 SecretFlow、平台统计与记忆服务是目标 runner，不代表后端已经连接；邀请不会真的发出，节点交付不会真的创建实例。
- 资源与耗时预估是粗略量级，不是报价或承诺。
- 上传检查只在浏览器本地读取文件的前 256KB 做结构检查，不上传；示例机构、节点交付、评测指标和交付物都是演示数据，项目进度只保存在浏览器本地。
- 不覆盖所有联邦方法；小众方法即使成熟也不收录，已删除的内容见 [DIMENSIONS.md](./DIMENSIONS.md) 的"未收录"。
- 当前不处理生产级多租户、计费、密钥托管、断点恢复和大规模调度。
