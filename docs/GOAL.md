# 项目目标

最后复核：2026-09-24

## 产品目标

Federation Studio 要做的是联邦任务的控制面，而不是重新实现所有联邦算法。

用户描述想完成的协作任务后，平台负责：

1. 把需求整理成一组有层次的配置，而不是暴露无约束的选项笛卡尔积。
2. 判断参与方的数据、模型或知识产物是否满足方法契约。
3. 生成不可变的 RunSpec，并在隔离的容器或沙箱中调用合适的执行后端。
4. 跟踪运行、评测结果和产物谱系，保留可审计记录。
5. 由 Agent 解释不兼容原因、给出修复建议，并处理硬规则之外的长尾问题。

平台统一的是配置、准入、编排、隔离、评测和追踪；具体算法由 Flower、NVFlare、FATE 或自定义 runner adapter 提供。

## 配置模型

配置按以下层次组织：

1. **工作负载**：用户想完成什么，如联合训练、纵向建模、联邦分析或 FedRAG。
2. **数据关系**：参与方的数据如何分布，如横向、纵向、混合或无训练数据协作。
3. **参与拓扑**：跨机构、跨设备、混合节点或本地模拟。
4. **协作策略**：在当前工作负载下使用哪一种算法或聚合策略。
5. **保护目标**：需要保护什么，再由平台映射为 SecAgg、DP、HE、MPC、TEE 等机制组合。
6. **方法专属参数**：模型、训练轮次、LoRA rank、实体对齐、索引和评测套件等。
7. **派生配置**：运行时、评测方式、输入契约和输出产物由平台自动解析。

## 当前阶段目标

当前里程碑是验证产品信息架构，而不是交付生产联邦系统：

- 前端完整表达上述分层配置。
- 每个工作负载只展示与它相关的策略和参数。
- 用户通过固定时间轴完成配置、上传、准入、沙箱、执行、评测和发布。
- 明确区分已实现、前端模拟和未实现能力。
- 保留一条 LoRA / Adapter 场景，作为下一阶段接真实 runner 的首条纵向切片。

## 成功标准

| 编号 | 标准 | 当前状态 |
|---|---|---|
| G1 | 9 类工作负载可在统一入口配置，且专属参数随选择变化 | 已完成 |
| G2 | 数据关系、拓扑、策略和保护目标会被工作负载约束 | 原型完成，规则仍需深化 |
| G3 | 配置到发布使用同一条可点击运行时间轴 | 已完成 |
| G4 | Agent 准入输出结构化规则、解释和修复建议 | 仅 UI 模拟 |
| G5 | RunSpec 能启动短生命周期隔离环境并流式回传状态 | 未实现 |
| G6 | 至少一条 LoRA 场景完成真实聚合、评测与产物发布 | 未实现 |
| G7 | 新增工作负载不需要改写通用向导和状态机 | 前端注册表已验证 |
| G8 | 系统具备身份、权限、审计和可重复部署能力 | 未实现 |

## 当前不承诺的能力

- 页面中的 SecAgg、差分隐私、同态加密、MPC 和 TEE 目前是保护配置，不代表协议已经实现。
- 页面中的 Flower、NVFlare、FATE 和沙箱是目标 runner，不代表后端已经连接。
- 上传步骤不会持久化真实文件；评测指标和发布产物为演示数据。
- 当前不处理生产级多租户、计费、密钥托管、断点恢复和大规模调度。
