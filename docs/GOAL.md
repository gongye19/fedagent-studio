# 项目目标

最后补充：2026-10-13（T78：任务内资源接入；部署状态见 PROGRESS）

T78当前用户入口：场景→任务类型→算法→提交或选择所需资源→运行。算法、数据规范和执行流程由平台提供，用户复用工作区数据／模型或在配置中接入；公用基准可试跑，正式任务至少绑定一份工作区数据。资源按数据、模型接口、执行环境管理，不要求先创建参与方。当前“我的资源”仍是共用工作区，不宣称多用户私有隔离；外部Agent服务、纵向和迁移执行保持未开放。

## G：产品目标

FedAgent Studio 是通用的联邦 Agent 平台：用户接入自己的数据、模型或执行环境，选择平台支持的算法组织协作，评估是否改善，并把产出用于自己的系统。真实跨机构运行时原始数据和标注留在本方；选择平台托管即把数据交给平台运营方。

各方之间只交换算法声明的内容，由服务端汇总后下发；交换什么、谁能读到，写在算法清单里，由平台执行。第一个算法 FoT 交换的是文本形式的解题经验（trace），服务端把它们汇成经验库。

用户先选场景，再选任务类型、算法和数据。平台负责：

1. 按场景、任务类型组织算法和数据。
2. 运行联邦任务：按算法声明的步骤在各方和服务端之间逐轮推进，支持暂停、继续和断点续跑。
3. 如实展示结果：本地基线与联邦之后的对比、负迁移、各轮产出和服务端实际收到的内容。
4. 让产出能被使用：发布为应用、试用、导出和 API 调用。
5. 支持平台托管与参与方本地执行；后续通过适配器连接用户已有 Agent 服务。没有自建 Agent 的用户也能使用算法提供的本方流程。
6. 方便扩展：算法、任务类型、判分方式、参与方的运行方式、数据格式和模型服务分开接入。在已有契约内增加实现复用核心；新增能力先补通用契约，不把所有新能力包装成“只装插件就能用”。

平台不自己发明联邦算法：第一个算法是已发表的 FoT（Federation over Text，arXiv:2604.16778），引擎基于已审计的复现器。Agent 相关的方法可以有创新，其他部分用主流、成熟的做法。

### T74：面向用户的边界

- 参与方是机构／节点，数据集是它持有的资源，Agent 执行能力是它完成算法步骤的方式；三者不能等同。一方可有多份数据，也可复用同一算法执行代码。
- 普通用户登记资源、选择已有算法、运行和使用成果；算法开发者／管理员负责新增插件和适配器。不要求普通用户编写医生／专家角色、部署整套 Agent 产品或上传可执行代码。
- 模型接口、已有 Agent 服务分别接入：前者提供模型推理，后者必须满足算法所需的输入、结果、轨迹／更新和回用能力；聊天 API 不能自动参加所有算法。
- FoT 保持“横向／数学推理／解题经验库”；EvoMedClaw 首先接“横向／医疗诊断／过程经验库”，共享核心流程。纵向、迁移以及新场景需落实角色、数据关系、执行和评估协议后才开放。
- 扩展任务类型应同时覆盖上传、校验、标签隔离、样本预览、评估、应用输入与输出；不能只增加一个算法选项。具体用户流程与验收见 [FLOW.md 的 T74 方案](./FLOW.md#t74从用户接入到成果使用的方案)，接口边界见 ARCHITECTURE §22。
- 后续对多用户开放前增加账号、资源归属与必要共享权限；维持简洁的现有导航，不预建大量无需求的管理模块。

## 第一版范围

- **场景**：横向联邦 Agent 可用，算法是 FoT；纵向和迁移显示为规划中，算法待定。
- **数据**：八份实际数学题库来自用户提供的FoT审计包、共300题，全部随代码保存并已导入，来源与哈希见MATH-DATA；也可以上传同格式题库。平台不保留空示例合作方或虚构样本。EvoMedClaw横向文本、独立医疗输入／评分和SDK适配已通过本地验证，公开MedQA107病例已下载并校验；生产导入状态见PROGRESS。
- **参与方**：第一版以平台托管为主；参与方本地的客户端（fedagent-client）已经能领取、执行和提交，安装包由平台提供（部署时构建）。
- **模型**：任意 OpenAI 兼容的接口，由用户在界面上配置，每个接口从接口提供的模型里选一个；现在接的是 David AI 的 gpt-5.6-luna。测试用的假模型只在本地开发和自动测试里有。
- **当前阶段**：FoT 真实模型链路已通过小规模试跑，部署仅在 Tailscale 内网；下一阶段先补通用数据／应用契约，再接 EvoMedClaw 横向流程。

## 当前不承诺的能力

- **FoT 的实际效果**：已知用 gpt-5.4-mini 跑三个种子没有复现论文的提升；论文结果来自 DeepSeek 和 Gemini。用假模型跑出的准确率和经验库只用来验证流程。
- **真实模型**：David AI 的 gpt-5.6-luna 已跑通完整流程；小试跑验证运行链路，不能据此证明 FoT 的效果。
- **命令行**：现在只有运维命令，按配置文件创建任务等命令以后加。
- **本地客户端**：能用，安装包由平台提供，上传前可以逐条确认（`--review`）；还没有发布到公共仓库，也没有过滤规则。
- **纵向和迁移**：没有算法。
- **预估**：FoT 正常路径调用数可计算，服务端汇总与重试有变化；医疗多轮问诊只能按分支给估算／上限。token、时长和费用也为估算。
