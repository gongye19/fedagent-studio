## G：产品目标

Federation Studio 是面向多种隐私协作任务的场景配置与运行控制台，而不是重新实现所有联邦算法。

用户按统一的维度分层逐层选择要完成的协作，平台收集输入或参与节点的声明，检查契约，生成执行计划，在隔离环境中调用适配的 runner，最后完成评测和产物追踪。

平台负责：

1. 用一套统一分层把主流联邦方法（以及大模型 / Agent 相关的前沿方法）组织起来，让用户一步步选到可运行的场景和策略，而不是暴露无约束的选项组合。
2. 判断参与方的数据、模型或知识产物是否满足方法契约。
3. 生成不可变的运行计划（前端为 FrontendRunPlan，后端为 RunSpec），在隔离的容器或沙箱中调用合适的执行后端。
4. 跟踪运行、评测结果和产物谱系，保留可审计记录。
5. 由 Agent 解释不兼容原因、给出修复建议，并处理硬规则之外的长尾问题。

平台统一的是配置、准入、编排、隔离、评测和追踪；具体算法由 Flower、NVFlare、FATE、mergekit 或自定义 runner adapter 提供。不同任务的差别落在"执行模式 + runner adapter"上。

## 配置模型

完整定义见 [DIMENSIONS.md](./DIMENSIONS.md)。

1. **协作目标**：想共同完成什么。
2. **各方投入**：每个参与方拿出来的是什么（本地数据、已训练产物、测试数据、Endpoint、索引、Skill）。
3. **数据关系**：仅在投入为本地数据时出现。
4. **参与方形态**：跨机构、端侧设备。
5. **模型形态**：仅在训练模型时出现，决定场景模板。
6. **协作策略**：只列当前场景可用的策略。
7. **安全与信任**：5 档保护预设，由能力矩阵判断。
8. **场景参数**：策略之外的可调项。

联邦对象、计算类型、执行模式、输入接入、runner、评测和输出由平台推导。

## 当前阶段目标

当前里程碑是验证维度分层和产品流程，而不是交付生产联邦系统：

- 前端完整表达 8 个维度及其依赖关系。
- 8 个场景模板都能通过逐层选择或模板快捷入口到达，并各自跑通模拟流程。
- 用户通过固定时间轴完成配置、输入接入、准入、沙箱、执行、评测和发布。
- 明确区分已实现、前端模拟和未实现能力。
- 分层合理后，再选两个结构差异大的例子实现后端 demo。

## 当前不承诺的能力

- 页面中的 SecAgg、差分隐私、同态加密、MPC 和 TEE 是保护配置，不代表协议已经实现。
- 页面中的 Flower、NVFlare、FATE、mergekit 和沙箱是目标 runner，不代表后端已经连接。
- 输入接入步骤不读取、不持久化文件内容；参与方、评测指标和发布产物是演示数据。
- 不覆盖所有联邦方法；小众方法即使成熟也不收录，已删除的内容见 [DIMENSIONS.md](./DIMENSIONS.md) 的"未收录"。
- 当前不处理生产级多租户、计费、密钥托管、断点恢复和大规模调度。
