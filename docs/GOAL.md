# 项目目标

最后复核：2026-09-29（T39：通用平台 + 控制台风格）

## G：产品目标

Federation Studio 是联邦 Agent 平台：让多个参与方的 Agent 在不交出题目、答案和原始数据的前提下一起变强。

参与方只上传文本形式的推理经验（trace）；服务端把各方经验汇成洞见库，再下发给所有参与方。平台不传模型参数，不需要梯度或标注。

用户先选场景，再选算法和数据。平台负责：

1. 按场景组织算法，按算法匹配能用的数据。
2. 运行联邦任务：按轮执行参与方步骤和服务端步骤，支持暂停、继续和断点续跑。
3. 如实展示结果：第 1 轮（本地）与最后一轮（联邦）的对比、负迁移、各轮洞见库和服务端实际收到的内容。
4. 让洞见库能被使用：发布、试用、导出和 API 调用。
5. 支持两种参与方运行位置：平台托管用于演示和算法验证，参与方本地用于真实的跨机构联邦。

平台不自己发明联邦算法：第一个算法是已发表的 FoT（Federation over Text，arXiv:2604.16778），引擎基于已审计的复现器。Agent 相关的方法可以有创新，其他部分用主流、成熟的做法。

## 第一版范围

- **场景**：横向联邦 Agent 可用，算法是 FoT；纵向和迁移显示为规划中，算法待定。
- **数据**：内置 8 个数学题库（来自 FoT 复现包，共 300 题），也可以上传同格式的题库。
- **参与方**：第一版以平台托管为主；参与方本地的客户端在架构中定义，尚未实现。
- **当前阶段**：先完成前端原型，把整体架构和使用方式定清楚；后端下一步实现。

## 当前不承诺的能力

- **任务运行和结果**：准确率、trace、洞见库和 token 都是前端模拟生成的示例数据，不代表 FoT 的真实效果。
- **FoT 的实际效果**：已知用 gpt-5.4-mini 跑三个种子没有复现论文的提升；论文结果来自 DeepSeek 和 Gemini。平台用哪个模型之后再定。
- **试用页的对比回答**：是示意。
- **API 和命令行**：接入后端后提供。
- **本地客户端**：尚未发布。
- **纵向和迁移**：没有算法。
- **模型接口**：只预留了默认接口，不保存密钥，不能测试连通；预估的 token、时长和费用是按口径估算的量级。
