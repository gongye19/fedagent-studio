# LifeStyle 饮食／运动语料准备（T146）

用户最新决定：**先准备数据，给出调用量后再确定**。本阶段只下载、筛选、分离与估算，没有生成新过程、提取新经验、调用推荐／评分模型或上线。旧 T145 的三题试跑仍然只是链路验证，不能用它声称有效。

## 哪些数据适合这个应用

| 来源 | 实际检查的范围 | 准备结果 | 用途 |
| --- | --- | --- | --- |
| MedQuAD | XML 实际 47,441 条，其中 16,407 条有答案；问题或答案情境宽筛 594 条，严格推荐依据 169 条 | 去除保留文档、超长、重复和抽审排除后，85 条生成候选 | 优先用于饮食、活动和慢病限制的经验依据 |
| MedMCQA | train 182,822、validation 4,183、test 6,150；有标签部分的问题宽筛 1,887 条，严格支持知识 79 条 | 14 条可选支持知识生成候选、3 条待主题复核的辅助评测候选 | 与推荐有关，但考试题不能直接当患者建议或现行指南 |
| MMLU-Pro Health | 官方 test 的 health 实际 818 条；问题关键词或 nutrition 来源命中 220 条 | 作者问题清单／清理子集交叉筛查与去重后，126 条待主题复核的辅助评测候选 | 全部保留评测，不拿测试题生成经验 |
| HealthBench | main 5,000 个模拟健康对话；末条问题宽筛 209 个 | 固定 96 个英文消费端饮食／活动问题，1,211 条原始评分规则 | 主要的独立开放式推荐评测，完整保留原对话和正负权重 |

这些数量表示相关性候选，**不表示经过医生审核或已经生成的经验数量**。来源有英文原文、历史知识、不同国家规范等限制；基准本身也可能进入基础模型预训练。不能将考试正确率提升等同于现实推荐效果或临床收益。

129道辅助选择题目前仅经过规则筛选和已知问题／重复清理，尚未逐题做主题适用性审核；其就绪程度低于已检查的推荐评测主题子集，不加入首批。下方包含这些题的扩展预算是假设场景，审核后应重新统计，不能直接启动。

MedMCQA 的严格规则初筛仍有大量误命中：固定 20 条样本中，Codex 仅判 5 条适合作支持知识；随后查看清理前全部 57 条训练候选，保守保留 14 条，其余隔离。固定 MedQuAD 样本 20 条中 19 条与推荐直接有关，1 条过于笼统的专科治疗排除。这里是 AI 对主题适用性的检查，没有医生事实核验；比例不能推广为全数据集准确率。

未入首批的内容留在 `review-pool.jsonl`：MedQuAD 427、MedMCQA 1,859、MMLU-Pro 86 条。它们是待复核材料，不计为准备好可直接提取的推荐依据。原始大库仍完整保留，后续可针对缺口扩筛，不为增加条数混入无关诊断、药物、手术、分子机制或补充剂剂量。

## 数据边界与分离

- 推荐依据的三个模拟来源：A 为 NIDDK（47 条）、B 为 NHLBI（13 条）、C 为 MedlinePlus／SeniorHealth（25 条）。三者来自 MedQuAD 的原始机构分区，**不是三家医院或真实站点病历**。MedMCQA 的 14 条单列为可选支持层，不默认混入首个推荐经验包。
- MedQuAD 按完整文档及 focus 分组，稳定哈希保留约 20% 主题组；43 条文档留出只保留，当前没有评分器，不计入评测调用。另保护 T145 的 7 条同文档／同主题材料，旧冒烟的所有文件保持不变。
- MedMCQA 仅 train 可进入学习候选；validation 做辅助评测。公开 test 的 `cop` 全是 -1，不能当最后一个选项或已知答案；parquet 有效答案编号是 **0–3**，与旧 README 示例的 1–4 不同。
- MMLU-Pro 保留完整选项和实际答案索引，支持最多 A–J、可变选项数。清理子集是同一数据的筛选标注，不能算额外数据或一边训练一边评测。其 few-shot validation 不进入新测试集。
- HealthBench 全部 5,000 对话都受保护；其中 96 条作为本次主题子集，不加入生成。最长选中上下文 3,135 字符，原有多轮消息全部保留，不强塞进 `profile/question` 或截断。hard／consensus 子集未另算数据。
- 跨来源近重复先保护评测，移除训练冲突；选项重排按题干和实际答案文字处理，不按字母比较。精确规范化＋词集合相似度和字符序列相似度均 ≥0.88；不能证明发现所有语义改写。本次实际比较 36,196 对，完整构建约 4 秒。重复 38 条、矛盾近重复 13 条隔离，不改标准答案。版本化抽审另隔离规则漏掉的问题。

生成候选不是上传用过程记录，`uploadableProcessRecord=false`。将来生成时 `profile` 明确“个人情况未提供”，不挂无关 Synthea 人物、不编造病史；MedQuAD 的目标问题专门询问饮食／活动建议、适用限制与信息缺口。原题、完整证据与来源另存。生成后还需任务合同校验和内容检查，不能把知识问答伪装成已经发生的真实就诊。

每个生成问题同时保留原始问题的区别，避免同一主题的不同资料被改成完全相同的问题。首批每个来源选10个不同主题组，不按文档编号连续取题。损坏的重复选项隔离为待复核；一次已发现的拼写变体重复也通过版本化审核编号排除。复核池同样标记保护主题，后续扩筛不得绕过留出边界。

支持知识层必须具有明确的主题审核通过记录；未来扩筛新命中而未审核的条目自动进入复核池，不会悄悄进入生成候选。可选支持层的生成问题包含完整原题和全部选项，并明确它是“公开考试的假设情境，不是提问者病史”；目标是分析对饮食／活动建议的适用启示，不是把残缺题干当用户提问或直接输出选项。审核证据文件写入实际审核过的原始候选及理由，包括被排除的条目，与固定抽审队列保持一致，不重新抽样冒充已经审核。

## 调用量：先决定规模，再运行

同一个模型做无经验／共享经验两组；不默认追加本站经验组。以下均为**首轮正常路径**、不含探测、重试、格式修正的估算，不是已发生调用或开销授权。

| 范围 | 生成过程与 FoT | 两组推荐回答 | 原版逐条规则评分 | 辅助选择题作答 | 合计 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 建议首批：30 条依据、24 道推荐题 | 92 | 48 | 682 | 0 | 822 |
| 全部推荐候选：85 条依据、96 道推荐题 | 257 | 192 | 2,422 | 0 | 2,871 |
| 可选加支持层：99 条依据、96 道推荐题、129 道知识题 | 299 | 192 | 2,422 | 258 | 3,171 |

生成侧为 `3N+2`：每条合成公开过程一次、反思一次、最多 3 条精选解题经验提取一次；全局归类、建库各一次。最终经验库保持 `paper-auto`，不预设最终条数。如需三个本站库额外 6 次；第三组推荐回答与原版评分，首批再加 365 次、全量再加 1,307 次。选择题确定性对答案，不调评分模型。

HealthBench 原版每条评分规则单独调用一次，**不是每题一次**，这也是主要调用来源。合并评分可以另行考虑，但需单列为修改后的评分协议，不能宣称与原版相同。当前平台的 1–12 条布尔规则评分器不能处理这些带负权重的规则。

输入／输出 token 规划区间由实际字符量及 T145 36 次已缓存调用校准，具体在 `call-estimates.json`。首批输入约 **82–410 万**、输出约 **13–129 万**；全推荐池输入约 **443–2,216 万**、输出约 **43–391 万**。区间包含来源重复、完整经验上下文和逐项评分重发上下文等假设；**不是账单或硬上限**。新生成长度、中文输出／英文原题和模型隐藏 token 都会影响它。没有核实 David AI 实际单价，不推算美元：`费用=输入token×输入单价/百万+输出token×输出单价/百万`。

上述全池合计仅是全局一次聚合的调用算术，**不表示能装进一个任务**。首个 FoT 任务的保守运行限制为 30 条记录／最多 90 个 trace；模型实际上下文窗口仍未核实，归类输出上限 32,768 token。生成后必须按真实序列化输入和输出空间预检，再决定能否扩大；不会偷偷改成分层聚合以塞进大池。分批任务需要额外聚合调用，跨批成果如何使用需在正式执行方案中确认。

后续仍需实现：扩展现有 50 次上限和每方单记录的本机实验运行器；HealthBench 完整对话＋逐条带符号评分通道；选择题作答／判分通道。专用通道需先统一输出语言，再按同模型／提示词／输入配对对照；失败单列，不挑只展示提升的题。本阶段未实现或运行这些付费步骤。

## 本机文件与复现

原档和候选位于忽略目录 `data/lifestyle-prep/corpus/final-20261118/`，不进入 GitHub。`sources/` 按具体提交、大小、SHA256 固定；`prepared/` 包含候选、分开的评测输入／参考、保留集、复核池、重复隔离记录、实际审核证据、数量及预算。改变代码／来源／审核规则必须用新目录，不覆盖旧结果。

工具只依赖 Python 3.12、httpx 0.28.1、duckdb 1.4.5；它们属于准备工具，不加入生产依赖。`fetch` 联网，`build` 离线；不导入平台、模型网关或运行器。审核政策只提交原始编号和原因，来源清单提交版本／许可依据，原文与实验产物留本机。

```sh
uv run --no-project --python 3.12 --with httpx==0.28.1 --with duckdb==1.4.5 \
  python -m tools.lifestyle.corpus fetch --directory data/lifestyle-prep/corpus/my-run
uv run --no-project --python 3.12 --with httpx==0.28.1 --with duckdb==1.4.5 \
  python -m tools.lifestyle.corpus build --directory data/lifestyle-prep/corpus/my-run
uv run --no-project --python 3.12 --with httpx==0.28.1 --with duckdb==1.4.5 --with pytest==9.0.2 \
  python -m pytest tools/lifestyle/corpus_tests -q
uv run --project server python -m pytest tools/lifestyle/tests -q
```
