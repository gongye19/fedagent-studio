# 项目演进

本文是按时间顺序的任务记录（`T<n>`）。当前状态以 [PROGRESS.md](./PROGRESS.md) 为准。

## T1：建立项目契约

定义通用联邦工坊的目标、兼容性判定、Run 状态机、评测闸门和自托管边界。

## T2–T4：完成前端骨架和运行编排

建立 React + TypeScript Demo，从多页面骨架收敛为单屏任务编排界面。

## T5：重建视觉系统

参考 Vercel / Railway，采用高密度、低装饰、清晰边界的工作台风格。

## T6：收敛到 LoRA 场景

为了让 Demo 可理解，先以 `lora-fedavg-v1` 表达方法、数据、保护、沙箱和评测流程。

## T7–T9：重构配置层级

去除重复副标题；恢复选择控件；将方法、加密、数据和方法专属参数拆成独立模块。

## T10–T11：改为时间轴向导

建立 Configuration、Data upload、Agent preflight、Provision、Execute、Evaluate、Publish 七步流程，并修正节点和连接线布局。

## T12：升级为分层联邦平台

重新审视“方法 / 加密 / 数据类型”三个维度，将其升级为工作负载、数据关系、参与拓扑、协作策略、保护目标和方法专属参数；加入 9 类工作负载及动态配置，保留 LoRA mock 作为后端迁移起点。

## T13：工程整理

统一项目介绍、目标、架构、流程、开发和决策文档；补充根目录忽略规则、版本与完整检查命令；准备首个 Git 基线提交。

- 类型：Change + Fix

- 状态：完成
- 相关：D52；ARCHITECTURE §12
- 用户要求：模型接口列表里去掉地址、"未指定模型的调用都走这里""已保存密钥"，只写接口名称，地址在编辑页里看；然后测试一遍，看还有没有问题。

  - **空回答让任务暂停，继续也没用**：中转偶尔回 200、空内容、0 token。FoT 把空回答当失败重试，但账本把那次空回答记成了成功的调用，重试时按同样的请求从账本取回，还是空的，3 次后暂停；继续后还会一样。改为：网关把"空回答且不计 token"当暂时性错误重试，不记成成功；单元某次尝试失败时，这次尝试的调用作废，重试时重新调用。点"继续"后这个任务跑完了。
  - **长回答被 Cloudflare 断开**：中转在 Cloudflare 后面，100 多秒没有响应就返回 524（HTML 错误页）。反思、归类这类长回答和难题的试用都碰到了，而且 524 不在重试范围里，报错还显示整段 HTML。改为流式请求（边生成边返回），5xx（含 520–524）都重试，HTML 错误页只显示标题；接口不支持流式参数时自动改用普通请求。本地客户端同样改了。
  - **试用要等两次调用排队**：带应用、不带应用的两次调用改为同时发。

  - 流式上线后：测试连接返回正常的 token 用量；之前 524 的难题试用，两次调用 53.5 秒、138.8 秒都完成了；复制出的任务 28 次调用全部成功、没有重试，其中两次归类 121.5 秒、110.3 秒（以前超过约 120 秒就 524）；
