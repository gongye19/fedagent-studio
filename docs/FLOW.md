# 使用流程

最后复核：2026-09-29（T39 改为通用平台 + 控制台风格）

平台是通用的：场景、算法、任务类型都来自注册表，页面不针对某个算法写死。FoT 是目前登记的唯一算法，用来做演示。

## 谁在用

| 角色 | 做什么 |
|---|---|
| 任务发起人（研究员、业务方） | 选场景、算法和参与方，发起联邦任务，看结果，把产出发布为应用 |
| 参与方 | 持有数据集。可以交给平台托管，也可以在自己的环境运行客户端，数据不出本地 |
| 管理员 | 管理参与方、算法和模型接口 |
| 外部 Agent、脚本 | 通过 API 或命令行做上面同样的事，权限和审计与界面一致（接入后端后提供） |

前端原型里只有一个使用者，演示发起人和管理员的全部操作。参与方的本地客户端还没有发布。

## 页面

和原来的 TrustFLAIR 平台一样分四块：

| 导航 | 做什么 |
|---|---|
| 首页 | 三个场景的入口（可用的场景直接"新建任务"）、参与方和数据等资源的数量、最近任务 |
| 联邦任务 | 任务列表（按名称搜索、按状态筛选）、新建任务、任务详情 |
| 应用 | 任务产出发布后的成果：试用、查看内容、接入 |
| 基础管理 | 参与方与数据、算法、模型接口 |

## 主流程：发起一个联邦任务

```text
首页 / 联邦任务 ─► 新建联邦任务 ─► 任务详情 ─► 发布为应用 ─► 应用：试用 / 内容 / 接入
                    基本信息 → 场景与算法 → 参与方与数据 → 运行配置 →（高级配置）
                                                         概览 · 进度 · 产出 · 配置
```

### 新建联邦任务

版式参考阿里云、AWS 的"创建实例"页：左边是分块的配置面板，每一行"左边字段名、右边选项"；右边是配置摘要和预估（窗口较窄时摘要移到下方，创建按钮固定在底部）。

| 面板 | 字段 | 控件 |
|---|---|---|
| 基本信息 | 任务名称 | 输入框，已填默认名称 |
| 场景与算法 | 场景 | 选项按钮：横向联邦 / 纵向联邦（规划中）/ 联邦迁移（规划中）；目前只有横向可用，已经选好 |
| | 算法 | 带单选的表格，比较各算法的说明、通信内容和产出；横向目前只有 FoT |
| | 任务类型 | 选项按钮，由算法决定（FoT 是"数学推理"，评估指标是准确率） |
| 参与方与数据 | 参与方 | 带复选框的表格：参与方、数据集、样本数、运行位置、状态；整行可点，表头全选；等待连接的参与方不能选，行里有"去连接" |
| 运行配置 | 运行方式 | 选项按钮：试跑 / 正式运行；试跑时再填每个数据集取几条样本 |
| | 轮次 | 选项按钮：2–6 轮；第 1 轮是各方单独作答的本地基线 |
| | 参与方模型、服务端模型 | 下拉，默认走预留的 LLM 接口 |
| 高级配置（默认收起） | 算法参数 | 按算法在注册表里登记的参数生成（FoT：洞见库条数、trace 密度、每条样本最多 trace、汇总重试上限），默认值即推荐值 |
| | 通用 | 并发数、随机种子、为某个参与方单独指定模型 |

右侧摘要列出场景、算法、参与方、运行方式和模型，下面是预估：调用次数精确计算，token、时长和费用按口径估算（费用要在"模型接口"里填了单价才显示）。

点"创建并试跑"进入任务详情。正式运行要先确认一次：宽屏时确认框出现在配置摘要里，窄屏时底部栏变成"开始正式运行？［取消］［确认开始］"。

上次没填完就离开的话，再打开时会保留原来的配置，顶部提示"已恢复上次没填完的配置"，可以"清空重填"。

### 任务详情

| 标签 | 内容 |
|---|---|
| 概览 | 主要指标（由任务类型决定，数学推理是准确率）的本地（第 1 轮）与联邦（最新一轮）对比、负迁移、产出条数；各参与方的变化图；明细表 |
| 进度 | 各轮进度，步骤名由算法定义（FoT 每轮 6 步）；当前轮显示各参与方进度；通信记录列出各方每轮上传的内容 |
| 产出 | 算法的产出物，每轮一版（FoT 产出洞见库）；可以把任意一版发布为应用 |
| 配置 | 创建时冻结的任务配置、算法参数、参与方快照；要修改就"复制为新任务" |

有结果时默认打开"概览"，还没有结果时打开"进度"。运行中和暂停的任务在标签下方显示总进度。

### 应用

任务产出发布后成为应用，和原平台的"应用"页一样：

- **试用**：输入问题、选模型，"不带应用 / 带应用"并排对比（前端原型只有示例问题的示意结果）。
- **内容**：查看产出的内容。
- **接入**：导出 JSON 放进自己 Agent 的提示词；API 和命令行接入后端后提供。

## 参与方怎么加入

在"基础管理 → 参与方与数据"里新增参与方，选运行位置：

| | 平台托管 | 参与方本地 |
|---|---|---|
| 谁运行 Agent | 平台 | 参与方在自己的环境运行客户端 `fedagent-client` |
| 数据集在哪 | 上传到平台 | 留在参与方本地，只登记描述 |
| 模型密钥 | 用平台配置的模型接口 | 用参与方自己的密钥 |
| 离开参与方的内容 | 平台能看到数据集；服务端步骤仍然只用交换内容 | 只有交换内容（FoT 是 trace），上传前可以逐条审查 |
| 适合 | 公开数据、演示、算法验证 | 真实的跨机构联邦 |

平台托管的参与方直接上传数据集（JSONL，每行一条样本）：

- 数据格式由任务类型决定。数学推理：`id`、`question` 必填，`answer`（标注）可以没有；不超过 20 MB。
- 文件在浏览器里检查：不是合法 JSON、缺字段、id 重复都会逐行指出（最多列 5 处），可以"改好后重新选择文件"。
- 检查通过后只保存描述（样本数、标注数、样本示例），不保存内容。接入后端后由后端存储。
- 保存按钮不可用时，旁边写着还缺什么；保存后页面顶部提示已添加。

本地参与方保存后显示"等待连接"，详情里有连接命令。连上平台后状态变为"在线"，它的数据集才能在新建任务里选。

## 管理员：算法和模型接口

- **算法**：列出注册表里的算法，以及每个算法适用的场景、任务类型、通信内容和产出。新算法以插件登记（见 ARCHITECTURE.md），页面不用改。纵向和迁移的算法待接入。
- **模型接口**：平台侧的模型调用都通过 OpenAI 兼容的 LLM API。现在只预留一个"默认 LLM 接口"，具体服务和模型之后再配置；接口没配置也能创建任务。接口列成表格，新增和编辑用同一个表单；API 密钥只保存在服务端，前端不保存。

## 规则

- 场景未选、所选场景的算法还在规划中、少于 2 个可用参与方、模型接口不存在、轮次超出算法允许的范围时，不能创建任务。
- 创建时冻结配置和参与方快照；之后删改参与方不影响已有任务。
- 运行中可以暂停；暂停后可以继续；取消后停在当前步骤，不能再继续。
- 每轮末尾生成一版产出，最后一版是最终成果；任意一版都可以发布为应用，同一版只发布一次。
- 本地参与方连上客户端之前不能加入任务。

## 原型里哪些是模拟的

- **任务运行**：是加速的模拟，几十秒就能跑完。每一步的真实耗时以预估为准。
- **指标、上传内容、产出、token 用量**：都由任务 id 确定性生成，刷新后不变。侧栏（窄屏在顶栏）始终标着"示例数据"。FoT 的产出和 trace 是英文，因为 FoT 的提示词是英文。
- **应用试用的对比回答**：是说明用的示意，不是真实模型输出。
- **真实执行的部分**：数据集检查在浏览器里真实执行，导出 JSON 真实生成文件。
- **数据保存**：所有演示数据保存在浏览器本地（localStorage）；侧栏底部可以重置。
