## T94：接入验证前置，任务只查连接（2026-10-27）

**核心流程**：数据上传即校验格式／内容；LLM保存后验证真实响应；Agent保存接口并读取协议后，用户明确选择算法与已有验证数据，以最小样本检查完整步骤和输出。通过的资源才可在任务中选择。新建仍为算法→任务→资源→快速连接检查→开始，不再在此运行诊断、经验提取或模型探测。

**关键状态**：待检查为空心圈，检测中旋转，完成为绿色勾，失败为红叉与原位原因／重试；不用成功说明段落。Agent接入验证后台持久化、可关闭窗口，列表自动更新，重开恢复；接口地址／密钥／协议及算法合同变更后不可沿用旧验证，名称修改保留。任务连接报告仍有资源指纹与15分钟有效期，刷新不重新发请求。

**页面布局**：复用任务原连接面板和资源目录；只显示资源或步骤短名。说明与费用放ⓘ，Agent验证参数折叠，错误只出现在对应行；不新增首页通知栏、仪表盘或资源分类。

**组件映射**：CheckStatus／CheckRows统一任务、数据、LLM、Agent的反馈，复用现有Icon、Panel、Radix Select／Dialog和ParamField；240ms勾画与800ms旋转，支持减少动态，轮询不重挂载。Agent合同检查迁入agents/contract_check，接入编排在agents/verification，任务checks只负责连接；验证凭据在resource_services/verification，所有准入后端校验。

**验收**：不能选未验证接口，修改接口不能沿用旧凭据；注册／修正同一记录不制造重复资源；接入实测业务输出、任务检查严禁POST模型生成或Agent /runs。LLM GET /models，列表不支持时HEAD聊天路由只证可达，不宣称重新验证推理／鉴权；Agent GET /capabilities核对兼容。各网络读超时5秒，独立接口两路并行，无付费请求。数据校验、失败重试、刷新恢复、后台列表更新及桌面／手机无溢出需浏览器验证；迁移0008保留原数据／密文，旧接口明确重新验证，不凭历史调用猜测通过。

**联邦任务**是平台上的一次协作：选定场景、任务类型和算法，几个参与方各出一份数据集，让各方的 Agent 协作几轮。各方之间只交换算法声明的内容；原始数据是否托管在平台由运行方式决定。完成后对比各方"单独作答"和"联邦之后"的效果，任务的产出可以发布为应用。所有场景和算法都用同一种联邦任务。

## 几个概念

这几个概念各管一件事，不混用：

| 概念 | 是什么 | 由谁定 |
|---|---|---|
| 场景 | 各方的数据怎么分布。横向：各方做同类任务，各有各的样本；纵向：同一批对象，各方掌握不同方面的信息；迁移：把已有领域的经验用到新领域 | 注册表 |
| 任务类型 | Agent 要做的事，例如数学推理；决定数据格式和评估指标 | 注册表 |
| 算法 | 各方怎么协作，例如 FoT。每个算法只属于一个场景，声明适用的任务类型、交换内容、产出、参数和每轮步骤 | 注册表 |
| 参与方 | 参加联邦的机构或节点，持有数据并执行本方步骤；能力还取决于算法版本、执行环境和模型。平台托管时运营方能访问托管原始数据，本地运行时原始数据留在本方 | 用户登记 |
| 数据集 | 属于某个参与方，一方可以有多份；现版登记时绑定场景和任务类型，任务中每方选一份。数据集本身不等于 Agent | 用户登记 |
| 联邦任务 | 一次协作：场景、任务类型、算法，加上几个参与方，每方出一份匹配的数据集 | 用户新建 |

纵向和迁移的算法接入后，参与方在任务里还会有角色（例如纵向的发起方和数据提供方、迁移的源方和目标方），由算法声明，在任务配置时分配；角色不是参与方或原始数据永久绑定的属性。

核心任务：用户让若干参与方在自己的数据上按选定算法协作，取得可评估、可复用的成果。输入是参与方资源、数据、模型与运行配置；输出是实际运行记录、评估与版本化产出。成功标准是完整任务可运行、数据边界可核对、产出可用；不以必然提升为前提。

1. 在“参与方与数据”选择已有参与方，或登记机构／节点及运行方式。
2. 为它添加数据：平台运行时上传，本地运行时由客户端登记本地文件；已有 Agent 服务只登记经适配器验证的数据描述。
3. 在现有新建任务页选择场景、任务类型、算法，绑定每方的数据版本、执行能力与必要模型。保留固定区域首次展示、解释通过 ⓘ、只列兼容可用候选。
4. 后端预检角色人数、数据格式／版本、标签、插件版本、执行能力和模型。缺项跟随字段显示，并提供对应资源入口；新建资源后回原配置，保留草稿，不增加顶部恢复提示。
5. 小规模试跑；查看各方真实阶段、结果和消耗，再决定正式运行。数据检查通过不等于运行环境或算法已就绪。
6. 查看本地基线与联邦结果及失败原因，发布选定产出版本。按任务类型试用，或导出／通过 API 接入自己的系统。

### 用户自己的东西如何接入

| 用户已有资源 | 用户操作 | 平台需要提供 | 当前状态 |
|---|---|---|---|
| 只有数据，没有 Agent | 登记参与方、上传兼容文件、选模型 | 运行算法提供的本方 Agent 流程 | FoT 与 EvoMedClaw 横向文本已实现，部署状态见 PROGRESS |
| 数据和模型都在本地 | 安装客户端与支持的算法包，配置本地数据和模型，再连接平台 | 领取本方步骤、心跳、结果与声明的更新提交 | 客户端已按任务类型检查文件和插件版本；自有服务适配未实现 |
| 已有 Agent／业务服务 | 经适配器登记服务、认证和能力，测试连接与一次实际操作 | 校验输入／输出、版本、状态、幂等、取消与经验更新协议 | 尚未实现，不能只填写聊天 API 地址就宣称支持联邦 |
| 自己的模型接口 | 登记 OpenAI 兼容接口，或安装提供者适配器 | 单独管理模型调用，不能把模型接口当 Agent 服务 | OpenAI 兼容已有；其他适配按需实现 |
| 新算法代码 | 由算法开发者写插件、管理员安装审核后的版本 | SDK、契约验证、注册表与版本兼容 | 算法插件机制已有；不在普通上传入口运行任意代码 |

已有 Agent 可以由本地适配器包装，无须重写它：提供诊断／推理结果和算法要求的过程记录，适配器负责提炼更新与回用产出。只有“返回一句回答”的服务，未提供轨迹或所需更新能力时，不能参加需要这些能力的算法。

### 数据接入

- 任务类型提供版本化数据规范、标签定义、模板和校验；算法声明额外必需信息，例如诊断轨迹、可请求的检查，不能只靠任务类型名称判断兼容。
- 先交付规范 JSONL 和模板下载，再对有明确需求的来源提供转换适配器。CSV 映射、数据库直连、影像存储不一次全部加入。模板说明与空结构不作为参与方、样本或任务写入生产库。
- 浏览器做编码、大小、解析等基础检查；语义检查由任务类型对应的权威规则完成。本地文件在客户端检查；后端对托管文件保存前复查。反馈显示行号和字段路径，错误不部分保存、不静默改原值。
- 医疗标签从嵌套结构中分离，评分可读，诊断提示默认不可读；生成经验使用的数据与最终评测病例分开，记录分组和切分版本。只有无标签数据时不能显示诊断准确率；算法需要标签的阶段必须明确拒绝或选择支持的模式。
- 原始数据资产不因换场景重复上传。后续将不可变原始版本与任务数据绑定分开，记录转换规则、来源哈希与兼容场景；保留现版字段兼容，按需求迁移，不立即改旧数据。

### 必要状态与反馈

| 对象／状态 | 显示与可操作内容 | 后续行为 |
|---|---|---|
| 上传／检查中 | 文件处真实处理状态，可重新选择；避免旧检查覆盖新文件 | 当前文件合格后可保存 |
| 文件错误 | 对应文件的行号、字段和修复原因 | 改文件后重查，不落库半份数据 |
| 连接未完成／能力不兼容 | 在资源管理里说明缺什么，提供安装／重连／版本修复 | 联邦任务候选只列兼容且可用资源 |
| 预检失败 | 对应配置原位反馈，定位并保留已填内容 | 修复后重新预检 |
| 排队／执行中 | 后端上报的站点、步骤和已完成量，允许已有暂停／取消操作 | 刷新从持久化状态恢复 |
| 断线／步骤失败 | 具体参与方、失败步骤、重试状态；当前超过限制暂停 | 修复后按检查点继续，旧尝试不能重复提交 |
| 完成／取消 | 实际结果与产出版本，完成可发布；取消保持已完成记录 | 删除遵循已有结束任务规则 |

当前失败通过“暂停＋原因”表达，不为了新文案先新增状态。等待人工、部分完成或独立失败状态仅在算法确实需要并实现对应后端语义后加入。

### 两个算法的首条用户链路

| | FoT（当前可运行） | EvoMedClaw（待开发） |
|---|---|---|
| 用户选择 | 横向／数学推理／FoT | 横向／医疗诊断／EvoMedClaw |
| 本方输入 | 自有数学题；参考答案用于评估 | 自有结构化病例、任务目标、检查证据；参考诊断仅评估使用 |
| 默认执行 | 插件解题、反思、提取解题经验 | 插件组织问诊、检查、必要会诊、诊断、过程卡提炼 |
| 自有系统适配 | 提供解答与所需经验生成过程 | 提供诊断与必要轨迹，支持经验卡更新和全局记忆回用 |
| 共享与成果 | 解题经验 → 中心经验库 | 精简过程卡／统计 → 全局医疗经验库 |
| 试用 | 输入数学问题 | 首版输入结构化文本病例；是否需要与真人连续问诊另行确定 |

EvoMedClaw 首版需要真实文本病例和独立留出评估；不复用八份数学题库，不把启发式 heldout_lift 当准确率提升。采用已验证的 no-coevolve 路径，完整共演化需先解决 MedAgentSim 依赖。其纵向分支仍需核验或实现，不提前标为可运行。

### 验收条件与实施顺序

先完成跨任务类型的数据、样本、标签与应用契约，并用医疗输入证明不再依赖 question／answer；保持 FoT 原 API 和既有数据可用。随后接入 EvoMedClaw 横向插件及平台／本地执行，再按用户的真实服务接入需求补一个适配器；不先做任意服务、任意文件、任意流程的通用编辑器。

验收至少覆盖：合法数据保存并可选；错误数据无半份保存且反馈准确；不兼容服务不可参加；托管与本地同插件可运行；原始数据／标签不进入未声明的交换；重试不重复计入更新；刷新／断线后可恢复；留出病例不参与经验生成；成果可在独立输入上试用与导出；新插件在现有契约内无需新增算法专属页面。多用户开放前补账号、资源归属和最小共享权限，保护数据、模型密钥、任务和应用；当前只有访问令牌，尚不具备这些能力。

## 主流程：发起一个联邦任务

```text
首页（点场景卡片）/ 联邦任务（点场景一栏的"新建联邦任务"）─► 这个场景的配置页 ─► 任务详情 ─► 发布为应用 ─► 应用
                    横向联邦：基本信息 → 任务类型与算法 → 参与方 → 运行配置 →（高级配置）
                                                         概览 · 进度 · 产出 · 配置
```

### 新建联邦任务

每个场景有自己的配置页，因为不同场景的任务要配置的东西不同（例如纵向要对齐样本、分发起方和数据提供方）。首页的场景卡片和"联邦任务"页每个场景的"新建联邦任务"进的是同一个配置页，没有不分场景的通用配置页。目前只做了横向联邦（`#/tasks/new/horizontal`，标题"新建横向联邦任务"）；纵向和迁移打开时说明算法还在规划中。

横向联邦的配置页，版式参考 AWS 控制台的"创建"页：

- 左边是分块的配置面板，面板里字段名在上、控件在下，两栏对齐；
- 基本信息、任务类型与算法、参与方、运行配置和高级配置从首次打开起全部展示；有依赖的控件保留在原位，置灰或提示先选择什么，不再逐块出现；
- 右边是配置摘要和预估；窗口窄于 1180px 时摘要移到下方，创建按钮固定在底部；
- 控件下方不放说明文字；可以不填的字段在字段名后写"（可选）"。

| 面板 | 字段 | 控件 |
|---|---|---|
| 任务配置 | 任务名称 | 输入框，已填默认名称（任务类型 + 打开页面的时间，例如"数学推理任务 09-29 17:35"） |
| | 任务类型 | 选项按钮，列出这个场景里有算法能处理的任务类型（目前是"数学推理"，评估指标是准确率），由用户选；最后留一个虚线的"更多类型 · 待接入"空位，表示之后还会有别的类型 |
| | 算法 | 首次打开就列出本场景的算法表，未选任务类型时置灰并提示"请先选择任务类型"；选好后筛选适配算法并启用。比较说明、通信内容和产出，由用户选；最后一行是"更多算法 · 待接入"的空位 |
| 参与方 | 参与方 | 区域和新增入口始终显示，未选算法时提示前置条件，选好后显示带复选框的表格。一行一个参与方，只列出登记了同一场景、同一任务类型数据集的参与方：参与方、数据集、样本数、运行位置。不预先勾选，整行可点，表头可以全选；每方出一份数据集，名下有几份时在行里的下拉框选用哪一份。只显示在线且有匹配就绪数据集的可用参与方；等待连接、离线或数据未就绪的资源在基础管理里处理。右上角"新增数据集""新增参与方"打开新增页，保存后回到这里；新数据集的场景和任务类型与任务一致、持有方在线、样本已就绪时直接选入 |
| 运行配置 | 运行方式 | 选项按钮：试跑 / 正式运行；试跑时在右边填每个数据集取几条样本 |
| | 轮次 | 字段始终显示，未选算法时置灰并提示"请先选择算法"；选择后按算法注册表显示可用轮次（FoT 是 2–6 轮）；鼠标悬停、聚焦或点按字段旁的 ⓘ 可以看到"第 1 轮是各方单独作答的本地基线" |
| | 模型 | 选项来自已登记接口，参与方模型、服务端模型分别可选（服务端不调用模型的算法没有该项）；即使只有一个也可打开选择，菜单只列这一项。接口待配置时保留“去配置接口”，配好后回到这里 |
| 高级配置（默认收起） | 算法参数 | 按算法在注册表里登记的参数生成（FoT：经验库条数、经验提取量、每条样本最多上传、汇总重试上限），默认值即推荐值，选项里标"（默认）"；每个参数旁有 ⓘ，通过浮层按需显示解释 |
| | 通用 | 并发数、随机种子；有多个模型时，还可以为某个参与方单独指定模型 |

右侧摘要列出场景、任务类型、算法、参与方、样本、运行方式和模型，下面是预估（由后端按算法声明的每一步用量和接口单价算出，配置停下 0.3 秒后更新）：

- FoT 参与方的正常路径调用次数按配置计算，服务端给出下限；其他算法按真实分支给估算或范围，重试另计；
- Token、时长和费用按口径估算；费用要设置了单价才显示，"未设置单价"直接链到这个接口的编辑页。

所选的模型接口还没配置地址和模型时，摘要底部写明还需要什么，不能创建。点"创建并试跑"进入任务详情，轻量通知"已创建…，开始试跑"；任务先"排队中"，轮到它时开始运行（同时运行的任务默认 1 个）。正式运行要先确认一次：居中确认框写明参与方数、样本数、轮次、时长和费用，以及"创建后配置不能修改，运行中可以暂停或取消"。桌面和手机均只有一个模态确认框，失败保留确认及原配置，可重试。

页面级“取消”已移除；“重置配置”紧邻右侧摘要标题，清空前确认。正式运行、重置及其他确认框仍保留取消操作。

上次动过配置、没创建就离开，再打开时静默恢复；复制配置也不显示顶部提示。没动过的草稿不保留，每次打开从头选。缺项和错误显示在对应字段，尝试开始时定位；重置入口在摘要旁。

### 任务详情

| 标签 | 内容 |
|---|---|
| 概览 | 主要指标（由任务类型决定，数学推理是准确率）的本地（第 1 轮）与联邦（最新一轮）对比、负迁移、产出条数；各参与方的变化图；明细表 |
| 进度 | 各轮进度，步骤名和每步完成后显示的结果都由算法定义（FoT 每轮 6 步）；步骤分参与方、服务端两组，当前轮显示各参与方进度，已完成任务默认展开最后一轮。通信记录列出各方每轮上传的条数，点数字看内容，整张表只占一个 Tab 停靠点，用方向键移动 |
| 产出 | 算法的产出物，每轮一版（FoT 产出经验库）。发布时固定所选轮次，核对来源任务、轮次、条数并填写应用名称（按任务名预填），发布后轻量通知并能"立即试用" |
| 配置 | 创建时冻结的任务配置、算法参数、参与方快照；要修改就"复制为新任务" |

有结果时默认打开"概览"，还没有结果时打开"进度"。排队、运行中和暂停的任务在标签下方显示当前步骤和步骤完成进度；只统计已完成步骤及样本，不猜测服务端执行中的百分比。未开始步骤的耗时写明“预计”。暂停用黄色，取消用灰色，标签、步骤和进度条一致，结束后不显示执行横幅。“取消任务”通过居中模态确认一次。

### 应用

任务产出发布后成为应用。应用和联邦任务、参与方与数据用同一套分类：

- 先按场景分块：横向联邦 / 纵向联邦 / 联邦迁移（规划中的场景写"规划中"）。每块一张表：应用（产出条数、第几轮之后的版本）、任务类型、产出（产出物和生成它的算法，例如经验库、FoT）、来源任务、发布时间；
- 任务类型是第二层分类：表格里单独一列，上方可以按任务类型筛选，也可以按名称搜索，对所有场景一起生效；
- 应用的场景、任务类型和算法在发布时从来源任务记下，来源任务删掉后应用仍在原来的类别里；
- 应用详情的标题下依次写场景、任务类型、算法、产出和条数、来源任务、发布时间，顺序和任务详情一致。

应用详情和原平台的"应用"页一样：

- **试用**：输入问题（可以填标准答案）、选模型，"不带应用 / 带应用"各调用一次模型，并排对比；填了标准答案时自动判分，无判分结果标为“未判分”，两侧均显示 token 用量。结果保留提交时的问题、标准答案和模型，可展开“本次问题”核对；修改输入后标题变为“上次对比结果”，重新运行成功后更新。执行时锁定输入，失败后保留输入并允许重试；手机上下排列。当前不增加试用历史，刷新后重新输入。
- **内容**：查看产出的内容。
- **接入**：导出 JSON 放进自己 Agent 的提示词；或者调用 API（`POST /v1/apps/{id}/apply`，开启访问令牌时带上令牌），回答方式和试用一样。

应用可以重命名，也可以撤下（先确认）；来源任务还在时可重新发布。来源任务已删除时，撤下提示明确不能从原任务再发布，可先导出要保留的内容。

## 参与方和数据集怎么登记

参与方和数据集在同一个页面"参与方与数据"里，按类分开：

- 和联邦任务、应用一样先按场景分块：横向联邦 / 纵向联邦 / 联邦迁移（规划中的场景写"规划中"），三块在同一页上下排，一眼看全；
- 每块一张表，只写参与方和数据：一行是一个参与方在这个场景下登记的一份数据集，列为参与方、数据集、任务类型、状态、样本数；块的标题旁写这一类共有几个参与方、几份数据集。名称与机构分行，等待连接／离线在独立状态列标出。参加了哪些任务属于联邦任务，这里不显示；
- 任务类型是第二层分类：表格里单独一列，上方可以按任务类型筛选，也可以按参与方或数据集名称搜索，对所有场景一起生效；
- 参与方本身不绑定场景：它在几个场景下有数据集，就出现在几块里；同一个参与方的几份数据集排在一起；
- 点开后先看数据集信息和参与方信息两个区域；样本与本地客户端连接按需展开，连接指南分安装、环境变量和运行三段，签发与复制对应段落，以及"为这个参与方新增数据集""删除数据集""删除参与方"（平台内置基准资源按既有保护规则处理）；手机上每行变成一张卡片，字段名写在值上面；
- 自己登记的数据集可以删除，但每个参与方至少留一份；要删最后一份，就删除参与方。已有任务里的记录不受影响。

**新增参与方**（页面右上角）：先填基本信息，再选运行位置（不预先选），然后登记它的第一份数据集。选好运行位置后，下方写明这一方的数据怎么处理（平台托管：平台能看到数据内容；参与方本地：只上传交换内容）。

**新增数据集**（页面右上角，或参与方详情里的"新增数据集"）：先选属于哪个参与方，再登记。

两处登记数据集的方式一样，每一步都由用户选：

1. 场景：横向联邦 / 纵向联邦（规划中）/ 联邦迁移（规划中）；
2. 任务类型：列出这个场景里有算法能处理的类型（目前是"数学推理"），它决定数据格式和评估指标；最后同样留一个"更多类型 · 待接入"的空位；
3. 数据：平台托管的参与方上传文件，参与方本地的只登记名称和说明。

| | 平台托管 | 参与方本地 |
|---|---|---|
| 谁运行 Agent | 平台 | 参与方在自己的环境运行客户端 `fedagent-client` |
| 数据集在哪 | 上传到平台 | 留在参与方本地，只登记名称和说明；样本数在客户端连上后上报 |
| 模型密钥 | 用平台配置的模型接口 | 用参与方自己的密钥 |
| 离开参与方的内容 | 平台能看到数据集；服务端步骤仍然只用交换内容 | 只有交换内容（FoT 是解题经验），上传前可以逐条审查 |
| 适合 | 公开数据、演示、算法验证 | 真实的跨机构联邦 |

平台托管的数据集是 JSONL 文件，每行一条样本：

- 数据格式由任务类型决定，选好任务类型后写在上传框里。数学推理：`id`、`question` 必填，`answer`（标注）可以没有；不超过 20 MB。
- 文件在浏览器里检查：不是合法 JSON、缺字段、id 重复都会逐行指出（最多列 5 处），可以"改好后重新选择文件"。
- 保存时把文件交给后端，后端用同一套规则再查一次，再存进平台的数据目录（按内容哈希保存，内容不会被改）。
- 保存按钮不可用时，旁边写着还缺什么；保存后回到列表并展开刚登记的这一行，轻量通知已添加。新登记的排在最前面。

本地参与方保存后显示"等待连接"。详情里写着在参与方环境里的连接方法：用平台提供的安装包装好客户端（需要 Python 3.12+），点"签发客户端令牌"（只显示一次，已经填进命令），在本地运行命令；加 `--review` 可以在上传前逐条确认。连上平台、上报样本数后状态变为"在线"，它的数据集才能在新建任务里选；超过 2 分钟没有心跳就算离线。

## 管理员：算法和模型接口

- **算法**：按场景分成三栏（横向、纵向、迁移），每栏列出这个场景下的算法卡片（名称、一句说明、任务类型、产出），最后一个虚线框是"待接入"的空位；规划中的场景只有空位。和其他列表页一样，上方可以按任务类型筛选。点一个算法打开它的详情页：概况、每轮步骤（参与方几步、服务端几步）、参数（默认值和说明）、来源论文和代码。新算法以插件登记（见 ARCHITECTURE.md），页面不用改。
- **模型接口**：平台侧的模型调用都通过 OpenAI 兼容的 LLM API，只登记真实接口。预留一个"默认 LLM 接口"（现在配置成 David AI）；用默认接口的任务要先填好地址和模型才能创建。每个接口选用一个模型：填好接口地址和 API 密钥后，"模型"变成下拉框，列出接口提供的模型；接口不提供模型列表时直接填模型名。要用同一家的另一个模型，就再登记一个接口。接口列成表格，每行只写选用的那个模型；新增、编辑是独立页面，单价可选；保存后可以"测试连接"，按任务实际会用的参数试一次；登记的接口可以删除，预留的接口不能删。API 密钥加密保存在服务端，只能写入、不能读出：编辑时留空表示不修改，可以勾选"保存时清除"。

## 规则

- 分类统一两层：先按场景（横向 / 纵向 / 迁移），再按任务类型。联邦任务、应用、参与方与数据三个列表页按场景分块、任务类型是表格的一列，算法页按场景分栏、卡片上写任务类型；四个页面上方都可以按任务类型筛选。模型接口是所有场景共用的基础设施，不分类。
- 场景未选、所选场景的算法还在规划中、少于 2 个可用参与方、模型接口不存在或没配置好、轮次超出算法允许的范围时，不能创建任务。
- 数据集只能用于同一场景、同一任务类型的联邦任务；每个参与方在一个任务里只出一份数据集。
- 创建时冻结配置和参与方快照；之后删改参与方和数据集不影响已有任务。
- 运行中可以暂停；暂停后可以继续；取消后停在当前步骤，不能再继续。
- 每轮末尾生成一版产出，最后一版是最终成果；任意一版都可以发布为应用，同一版只发布一次。
- 本地参与方连上客户端之前不能加入任务；样本还没就绪的数据集（平台托管的待导入、本地的待上报）不能选入任务。
- 不可逆的操作都在原地确认一次，不用浏览器弹窗：取消任务、删除任务、删除参与方、数据集和接口、撤下应用、放弃或清空新建任务的配置。

## 运行和数据

- **任务运行是真实的**：后端按算法声明的步骤逐轮执行，每一步的结果写进数据库后才推进；暂停、继续、取消、服务重启之后都从检查点继续，已经完成的模型调用不重复计费。
- **测试用假模型**：只在本地开发和自动测试里有，部署的平台上只有真实接口。用它跑的任务在标题旁标"假模型"，回答由算法插件按固定规则生成，准确率和经验库只用来验证流程。
- **真实模型**：在"模型接口"里配置任意 OpenAI 兼容的接口。FoT 的解题经验和经验库是英文，因为 FoT 的提示词是英文。
- **数据保存**：参与方、数据集、任务、应用都保存在后端（服务器的数据目录）。浏览器里只保存没创建的新建任务配置（开启访问令牌时还有令牌）。

### 删除联邦任务

任务列表每行右侧有“删除”，已结束任务的详情页也有“删除任务”。居中确认框说明任务配置、结果和运行记录永久删除，参与方、数据集、已发布应用及费用账本保留。排队、运行和暂停中的任务须先取消，等任务结束后再删除；进程尚未退出时后端提示稍后重试。确认默认聚焦取消，Esc／取消返回触发操作，不跳顶；提交中锁定关闭，失败留在对话框中重试。删除成功后列表更新并浮层通知，关联应用显示“来源任务已删除”，仍可试用、导出和接入。
