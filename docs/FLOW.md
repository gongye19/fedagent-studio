# 使用流程

最后复核：2026-09-28（T33）

## 谁在用

| 角色 | 做什么 |
|---|---|
| 任务发起人（研究员、业务方） | 选场景、算法和数据，发起联邦任务，看结果，发布洞见库 |
| 参与方 | 持有题库。可以把题库交给平台托管，也可以在自己的环境运行客户端，题库不出本地 |
| 管理员 | 配置模型接口，管理用户和权限 |
| 外部 Agent、脚本 | 通过 API 或命令行做上面同样的事，权限和审计与界面一致（接入后端后提供） |

前端原型里只有一个使用者，演示发起人和管理员的全部操作。参与方的本地客户端还没有发布。

## 主流程：发起一个横向联邦任务

```text
联邦任务（首页）─► 新建联邦任务 ─► 任务详情 ─► 发布洞见库 ─► 洞见库：试用 / 导出 / API
                    场景 → 算法 → 数据 → 运行设置    结果 · 进度 · 洞见库 · 配置
```

### 1. 选场景

在首页点"新建联邦任务"，在"场景"里点一张卡片。每张卡片写着这个场景做什么、各方需要带什么数据。

- 横向联邦 Agent：可用。
- 纵向联邦 Agent、联邦迁移 Agent：规划中，卡片置灰，不能选。

上次没填完就离开的话，再打开时会保留原来的配置，顶部提示"已恢复上次没填完的配置"，可以点"重新开始"清空。从任务详情"复制为新任务"进来时，提示的是"已带入原任务的配置"。

### 2. 选算法

横向只有 FoT 一个算法，所以不用选，直接显示"FoT · Federation over Text"和一句说明。以后一个场景有多个算法时，才会出现算法卡片。展开 FoT 可以看到：

- 每轮 6 步：参与方各自执行解题、反思、提取 trace，服务端执行汇总、关系分析、生成洞见库。
- 留在参与方的内容：题目、标准答案、解答全文、模型与密钥。
- 适用数据、评分方式、论文和代码来源。

### 3. 选数据

只列出算法能处理的数据（FoT 目前是数学推理题），默认全选能用的数据。

- 每份数据由一个参与方持有，一份数据就是一个参与方 Agent，至少选 2 份。
- 数据是一张带复选框的表格，按"添加的参与方 / 内置示例"分组，和"参与方与数据"页的分组一致。每行写着名称、说明、题数和来源；只有例外（参与方本地、离线、没有答案）才会用标签标出。没有答案的题也能参与联邦，只是不计准确率。
- 点行里任意位置都能勾选，表头的复选框可以全选或清空；表格上方显示已选几份、共多少题。
- 持有方不在线的数据（例如还没连上客户端的本地参与方）置灰不能选，行里有"去连接"入口。
- 区块右上角的"新增参与方"可以去登记参与方或上传题库。

### 4. 运行设置

推荐值已填好，一般只需要确认：

- 运行方式：两张卡片，"试跑"（每份只取前 5 题）和"正式运行"，卡片底部写着各自的调用次数和时长，方便比较。建议先试跑，流程和费用确认后再正式运行。
- 轮次（下拉，2–6 轮，默认 3 轮）：第 1 轮还没有洞见库，就是各方单独作答的本地基线。
- 参与方模型、服务端模型（下拉）：默认都走预留的 LLM 接口（服务和模型之后再配置）。服务端每轮一次读完所有 trace，配置时要选长上下文的模型。
- 高级设置（默认收起，改过的项数会显示在标题上）：
  - 洞见库条数（论文默认、上游代码公式、固定 11 或 37 条）、trace 密度：下拉，选中项的说明写在下方
  - 每题最多 trace 数、汇总重试上限、随机种子、并发数
  - 为个别参与方指定模型：默认所有参与方用同一个模型，需要时点"添加"逐条加例外

右侧是任务配置清单（列出已选的参与方），还有预估。窗口较窄时清单移到页面底部，"开始试跑"按钮固定在屏幕下方。

- 调用次数精确计算：题数 × 3 步 × 轮次，服务端每轮至少 2 次。
- token、时长和费用按公开的口径估算。费用要在"模型接口"里填了单价才显示。

点"开始试跑"进入任务详情。正式运行时，按钮会先弹出一段确认，列出调用次数、token、时长和费用，确认后才开始。

### 5. 看任务详情

| 标签 | 内容 |
|---|---|
| 结果 | 平均准确率（及相对第 1 轮的变化）、负迁移、洞见库条数、token；各参与方从第 1 轮到最新一轮的变化图；"本地 vs 联邦"对比表 |
| 进度 | 已完成的轮次折成一行摘要，当前轮展开 6 步和各参与方进度；下面是服务端收到的全部 trace（每方每轮的条数，点数字看内容）；可以暂停、继续、取消 |
| 洞见库 | 每轮后生成的版本、与上一版相比新增了什么；关系分析把 trace 分成了哪些类、各类来自哪些参与方；可以发布任意一版 |
| 配置 | 创建时冻结的运行设置、参与方快照、复现参数、审计记录（接入后端后记录配置、提示词和数据的哈希） |

有结果时默认打开"结果"，还没有结果时打开"进度"。运行中和暂停的任务在标签上方显示总进度。配置不能改，要改就"复制为新任务"。

### 6. 发布并使用洞见库

在任务详情的"洞见库"里发布一版，发布后出现在"洞见库"页面：

- **洞见**：按类别浏览。
- **试用**：选模型，输入一道新题，"不带库 / 带库"并排对比。
- **接入方式**：
  - 导出 JSON，格式与 FoT 的 `library_r{n}.json` 相同，放进自己 Agent 的提示词。
  - 通过 API 或命令行调用（接入后端后提供）。

## 参与方怎么加入

在"参与方与数据"里新增参与方，选运行位置：

| | 平台托管 | 参与方本地 |
|---|---|---|
| 谁运行 Agent | 平台 | 参与方在自己的环境运行客户端 `fedagent-client` |
| 题库在哪 | 上传到平台 | 留在参与方本地，只登记描述（名称、题数） |
| 模型密钥 | 用平台配置的模型接口 | 用参与方自己的密钥 |
| 离开参与方的内容 | 平台能看到题库；服务端步骤仍然只用 trace | 只有 trace，上传前可以逐条审查 |
| 适合 | 公开数据、演示、算法验证 | 真实的跨机构联邦 |

平台托管的参与方直接上传题库（JSONL，每行一道题）：

- 必填 `id` 和 `question`，`answer` 可以没有。
- 文件在浏览器里检查：不是合法 JSON、缺字段、id 重复都会逐行指出，改好后重新选择。
- 检查通过后只保存描述（题数、带答案的题数、样例题），不保存题目内容。接入后端后由后端存储。

本地参与方保存后显示"等待连接"。参与方安装客户端、登记题库并连上平台后，状态变为"在线"，它的题库才会出现在新建任务的数据列表里。

## 管理员：模型接口

- 平台侧的模型调用都通过 OpenAI 兼容的 LLM API。现在只预留一个"默认 LLM 接口"，具体服务和模型之后再配置；新建任务时模型默认就用它，接口没配置也能创建任务。
- 接口列成一张表（名称、地址、模型、并发上限、单价、被几个任务使用）；新增和编辑用同一个表单，填好地址和模型后"待配置"标签消失。
- 需要时可以另外登记接口和模型，在任务的高级设置里给个别参与方单独指定。
- 单价用于新建任务时的费用预估。
- API 密钥只保存在服务端，前端原型不保存密钥，也不能测试连通。

## 规则

- 场景未选、所选场景的算法还在规划中、少于 2 份可用数据、模型未选、轮次超出 2–6 轮时，不能创建任务。
- 创建时冻结配置和参与方快照；之后删改参与方不影响已有任务。
- 运行中可以暂停；暂停后可以继续；取消后停在当前步骤，不能再继续。
- 每轮末尾生成一版洞见库，最后一版是最终成果；任意一版都可以发布，同一版只发布一次。
- 本地参与方连上客户端之前不能加入任务。

## 原型里哪些是模拟的

- **任务运行**：是加速的模拟，几十秒就能跑完。每一步的真实耗时以预估为准。
- **准确率、trace 数、洞见库内容、token 用量**：都由任务 id 确定性生成，刷新后不变。侧栏（手机上是顶栏）始终标着"示例数据"。洞见和 trace 的文字是英文，因为 FoT 的提示词是英文，真实输出也是英文。
- **试用页的对比回答**：是说明用的示意，不是真实模型输出。
- **真实执行的部分**：题库检查在浏览器里真实执行，导出 JSON 真实生成文件。
- **数据保存**：所有演示数据保存在浏览器本地（localStorage）；侧栏底部可以重置。
