# 运行流程

最后复核：2026-09-24（T23）

所有场景共用一条七步时间轴。左侧只展示当前步骤，用户可以"下一步"推进，也可以点击右侧节点回看。点击节点只改变查看位置，不会绕过状态机。

## S1 Configuration

用户按 [DIMENSIONS.md](./DIMENSIONS.md) 的 3 个维度选择。第一步先选场景（维度 1），子项 1.1–1.6 自动填好；没选场景时子项全部置灰。之后子项中会离开该场景的选项置灰且不能取消；换场景直接点另一个，再点一次当前场景即取消。维度 2–3（策略、保护）是单独的卡片，已选选项再点一次即取消。所有候选项始终展开，右侧实时显示平台推导结果。

- 当前：真实前端配置逻辑，生成 `FrontendRunPlan`。
- 后端：保存配置草稿，服务端重新校验并生成版本化 RunSpec。

## S2 Data & participants（数据接入）

1. **数据要求**：按场景和各方投入列出本次需要的数据格式、必需字段和最少条数。
2. **匹配到的联邦数据**：从平台已登记的数据中，按场景和子项（例如参与方形态、模型类别）自动匹配，默认勾选前几份，用户可以增减。数据留在各参与方本地，平台只登记契约和摘要；纵向场景标出 Guest / Host 角色。
3. **上传自己的数据**：用户上传后，由 Agent 检查格式、文件大小、必需字段和记录条数。通过则作为"我方上传"加入本次运行；不通过则逐项说明原因并给出修改建议。
4. 所选数据达到最少份数、且没有检查中或未通过的上传时，才能开始准入检查。

同时选择执行预设（快速验证 / 标准运行）和运行环境（当前只有前端模拟）。

- 当前：已登记的联邦数据是演示目录；上传文件只在浏览器本地读取前 256KB，真实解析 JSONL / JSON / CSV 的字段和条数，二进制权重只检查格式和大小，不上传、不保存。
- 后端：分片上传、对象存储、摘要计算、病毒扫描、manifest 提取、节点身份与连通性检查。

## S3 Agent preflight

硬规则检查场景路径、参与方数量、输入契约、保护与计算类型、runner 能力，以及场景特有规则（例如纵向必须有持有标签的 Guest、SecAgg 少于 3 方时提示）。Agent 把结构化结果翻译成说明，不能覆盖拒绝。

- 当前：确定性的规则模拟 + Agent 说明文案。
- 后端：policy engine + 只读 Agent，输出可审计 `PreflightReport`。

## S4 Provision sandbox

冻结运行计划，按执行模式创建协调方沙箱，挂载只读输入，设置默认拒绝的网络策略。

- 当前：模拟进度和日志，显示协调方与参与方侧的位置。
- 后端：Docker、Kubernetes Job 或微虚拟机。

## S5 Execute

按执行模式运行：多轮聚合、单轮聚合、PSI + 纵向协议、产物合并、查询融合或分布式评测。控制面只消费标准化状态、日志摘要和候选输出。

- 当前：每个场景用自己的执行模式模拟，并显示真实耗时预估。
- 后端：Flower、NVFlare、FATE、mergekit 或自定义 adapter。

## S6 Evaluate

在独立评测环境中对比基线与候选结果，按闸门规则（不低于基线、下降不超过阈值、不高于上限）判断。未通过闸门的结果不能发布。

- 当前：每个场景的演示指标和闸门。
- 后端：版本化 evaluation suite 和不可绕过的发布闸门。

## S7 Publish

评测通过后，用户选择发布范围（仅创建者 / 全部参与方 / 指定参与方）并手动确认发布。发布后可以查看冻结的运行计划。

- 当前：模拟发布，不生成真实文件。
- 后端：artifact registry、访问控制、审计记录和生命周期策略。

## 状态约束

- S1 维度未全部答完，不能进入 S2 的运行。
- S2 参与方少于场景要求，不能开始准入。
- S3 未通过，不能 provision，后续阶段都不会运行。
- 运行计划冻结后修改配置必须创建新 Run。
- runner 失败只能重试当前阶段或从快照恢复，不能伪造后续成功状态。
- S6 未通过，不能发布；S7 必须由用户确认。
