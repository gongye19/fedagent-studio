# 运行流程

最后复核：2026-09-25（T26）

所有场景共用一条七步时间轴。左侧只展示当前步骤，用户可以"下一步"推进，也可以点击右侧节点回看。点击节点只改变查看位置，不会绕过状态机。

## S1 Configuration

用户按 [DIMENSIONS.md](./DIMENSIONS.md) 的 3 个维度选择。第一步先选场景（维度 1），场景按运行方式分为"连接节点 · 多轮运行"和"上传文件 · 一次完成"两组；横向联邦训练的子项 1.1 模型类别、1.2 共享方式自动填好，可调整但不能取消；其他场景不显示子项。换场景直接点另一个，再点一次当前场景即取消。维度 2 协作策略、维度 3 安全与隐私是单独的卡片，已选选项再点一次即取消。所有候选项始终展开，选定场景后协作策略只列该场景的；右侧实时显示平台推导结果（手机端改为顶部进度条，运行计划移到下方）。

- 当前：真实前端配置逻辑，生成 `FrontendRunPlan`。
- 后端：保存配置草稿，服务端重新校验并生成版本化 RunSpec。

## S2 Data & participants（数据接入）

这一步随运行方式不同：

**连接节点（横向 / 纵向联邦训练）**，照 Flower 的方式：平台是 SuperLink，各参与方是 SuperNode（纵向用 NVFlare 的客户端）。

1. **数据要求**：各节点本地数据要满足的格式（例如 LoRA 时是指令 JSONL，纵向时是带主键的特征表）。数据留在节点本地，平台不读取。
2. **已连接的节点**：列出已连接平台的参与方节点，默认勾选前几个；纵向标出标签方和特征方。
3. **连接我方节点**：给出启动步骤和命令（节点主动连接平台，不需要开放端口）；demo 里点"模拟我方节点上线"。
4. 同时选择执行预设（快速验证 / 标准运行，决定轮次）。

**上传文件（联邦统计分析 / Agent 记忆联邦）**：

1. **数据要求**：统计汇总表（分组列 + count，均值方差另加 sum、sum_sq）或记忆文件（JSONL，每条含 content）。
2. **其他参与方已提交**：勾选参加本次运行的文件。
3. **上传我方文件**：由 Agent 检查格式、文件大小、必需字段和记录条数，通过则加入本次运行，不通过则逐项说明原因和修改建议。

参与方达到最少数量，且没有检查中、未通过的上传或连接中的节点时，才能开始准入检查。运行环境当前只有前端模拟。

- 当前：已连接的节点和已提交的文件是演示数据；我方节点上线是模拟；上传文件只在浏览器本地读取前 256KB，真实解析 JSONL / JSON / CSV 的字段和条数，不上传、不保存。
- 后端：SuperLink / NVFlare 服务端、节点证书签发与身份认证、节点在线状态；文件的分片上传、对象存储、摘要计算、病毒扫描、敏感信息扫描。

## S3 Agent preflight

硬规则检查场景路径、参与方数量、输入契约、保护与计算类型、runner 能力，以及场景特有规则（例如纵向必须有标签方、SecAgg 少于 3 方时提示）。Agent 把结构化结果翻译成说明，不能覆盖拒绝。

- 当前：确定性的规则模拟 + Agent 说明文案。
- 后端：policy engine + 只读 Agent，输出可审计 `PreflightReport`。

## S4 Provision sandbox

冻结运行计划，按执行模式创建协调方沙箱，挂载只读输入，设置默认拒绝的网络策略。

- 当前：模拟进度和日志，显示协调方与参与方侧的位置。
- 后端：Docker、Kubernetes Job 或微虚拟机。

## S5 Execute

按执行模式运行：多轮联邦（下发 → 本地训练 → 回传 → 合并，重复多轮）、纵向协议（隐私求交 + 加密交换中间结果）、单轮汇总（由计数和求和算整体结果）、单轮合并（记忆脱敏、去重、处理冲突）。控制面只消费标准化状态、日志摘要和候选输出。

- 当前：每个场景用自己的执行模式模拟，并显示真实耗时预估。
- 后端：Flower（横向）、NVFlare（纵向）、平台统计服务和记忆合并器。

## S6 Evaluate

在独立评测环境中对比基线与候选结果，按闸门规则（不低于基线、下降不超过阈值、不高于上限）判断。未通过闸门的结果不能发布。

- 当前：每个场景的演示指标和闸门。
- 后端：版本化 evaluation suite 和不可绕过的发布闸门。

## S7 Publish

评测通过后，用户选择发布范围（仅创建者 / 全部参与方 / 指定参与方）并手动确认发布。发布后可以查看冻结的运行计划。

- 当前：模拟发布，不生成真实文件。
- 后端：artifact registry、访问控制、审计记录和生命周期策略。

## 状态约束

- S1 维度未全部答完，不能进入 S2 的运行。
- S2 参与方少于场景要求，不能开始准入。
- S3 未通过，不能 provision，后续阶段都不会运行。
- 运行计划冻结后修改配置必须创建新 Run。
- runner 失败只能重试当前阶段或从快照恢复，不能伪造后续成功状态。
- S6 未通过，不能发布；S7 必须由用户确认。
