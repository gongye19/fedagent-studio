# 使用流程

最后复核：2026-09-29（T43 参与方和数据集分开管理；数据集登记时选定场景和任务类型；新建任务按参与方勾选，每方出一份数据集）

平台是通用的：场景、任务类型、算法都来自注册表，页面、预估和任务推进都不针对某个算法写死。FoT 是目前登记的唯一算法，用来做演示。

**联邦任务**是平台上的一次协作：选定场景、任务类型和算法，几个参与方各出一份数据集，让各方的 Agent 协作几轮。各方之间不交换原始数据，只交换算法需要的内容。完成后对比各方"单独作答"和"联邦之后"的效果，任务的产出可以发布为应用。所有场景和算法都用同一种联邦任务。

## 几个概念

这几个概念各管一件事，不混用：

| 概念 | 是什么 | 由谁定 |
|---|---|---|
| 场景 | 各方的数据怎么分布。横向：各方做同类任务，各有各的样本；纵向：同一批对象，各方掌握不同方面的信息；迁移：把已有领域的经验用到新领域 | 注册表 |
| 任务类型 | Agent 要做的事，例如数学推理；决定数据格式和评估指标 | 注册表 |
| 算法 | 各方怎么协作，例如 FoT。每个算法只属于一个场景，声明适用的任务类型、交换内容、产出、参数和每轮步骤 | 注册表 |
| 参与方 | 参加联邦的机构或节点，是一道隐私边界，原始数据不出本方。参与方本身不绑定场景，能参加哪些任务由它登记的数据集决定 | 用户登记 |
| 数据集 | 属于某个参与方。登记时选定场景和任务类型，只能用于同一场景、同一任务类型的联邦任务 | 用户登记 |
| 联邦任务 | 一次协作：场景、任务类型、算法，加上几个参与方，每方出一份匹配的数据集 | 用户新建 |

纵向和迁移的算法接入后，参与方在任务里还会有角色（例如纵向的发起方和数据提供方、迁移的源方和目标方），由算法声明，登记数据集时一并选定。

## 谁在用

| 角色 | 做什么 |
|---|---|
| 任务发起人（研究员、业务方） | 选场景、任务类型、算法和参与方，发起联邦任务，看结果，把产出发布为应用 |
| 参与方 | 持有数据集。可以交给平台托管，也可以在自己的环境运行客户端，数据不出本地 |
| 管理员 | 管理参与方、数据集、算法和模型接口 |
| 外部 Agent、脚本 | 通过 API 或命令行做上面同样的事，权限和审计与界面一致（接入后端后提供） |

前端原型里只有一个使用者，演示发起人和管理员的全部操作。参与方的本地客户端还没有发布。

## 页面

和原来的 TrustFLAIR 平台一样分四块：

| 导航 | 做什么 |
|---|---|
| 首页 | 居中的"选择联邦场景"，只放横向、纵向、迁移三张卡片。每张卡片上一张示意图说明数据在各方之间怎么分（横向按样本分、纵向按字段分、迁移从已有领域到新领域）。可用的场景整张卡片都能点，点进去就是这个场景的联邦任务配置；规划中的灰显、不能点。任务、参与方、数据集、接口、应用都在各自的页面，首页不重复 |
| 联邦任务 | 任务列表（标题下一句话说明联邦任务是什么；按名称搜索、按状态筛选）、新建任务、任务详情 |
| 应用 | 任务产出发布后的成果：试用、查看内容、接入 |
| 基础管理 | 侧栏里和首页、联邦任务、应用同一级的一项，点开后展开参与方与数据、算法、模型接口（当前页在这几页时自动展开）；新增参与方、新增数据集、新增和编辑接口都是独立页面（和 AWS 的创建页一样），有面包屑和自己的地址 |

窗口窄于 900px 时侧栏收成顶栏，导航放进"菜单"，展开后和侧栏一样是一列。所有页面的浏览器标题都是"页面名 · FedAgent Studio"。创建、保存、发布、删除之后，页面顶部出现一条结果提示（可以"知道了"关掉），换到别的页就收起。

## 主流程：发起一个联邦任务

```text
首页（点一种场景）/ 联邦任务 ─► 新建联邦任务 ─► 任务详情 ─► 发布为应用 ─► 应用：试用 / 内容 / 接入
                    基本信息 →（场景、）任务类型与算法 → 参与方 → 运行配置 →（高级配置）
                                                         概览 · 进度 · 产出 · 配置
```

### 新建联邦任务

版式参考 AWS 控制台的"创建"页：

- 左边是分块的配置面板，面板里字段名在上、控件在下，两栏对齐；
- 右边是配置摘要和预估；窗口窄于 1180px 时摘要移到下方，创建按钮固定在底部；
- 控件下方不放说明文字；可以不填的字段在字段名后写"（可选）"。

| 面板 | 字段 | 控件 |
|---|---|---|
| 基本信息 | 任务名称 | 输入框，已填默认名称（任务类型 + 打开页面的时间，例如"数学推理任务 09-29 17:35"） |
| 场景、任务类型与算法 | 场景 | 从首页点场景进来时已经选好：这一项不再显示，面板标题变为"任务类型与算法"，页面标题旁写明场景，面包屑回到首页。从"联邦任务"页进来时是选项按钮：横向联邦 / 纵向联邦（规划中）/ 联邦迁移（规划中），不预先选 |
| | 任务类型 | 选了场景才出现。选项按钮，列出这个场景里有算法能处理的任务类型（目前是"数学推理"，评估指标是准确率），由用户选；最后留一个虚线的"更多类型 · 待接入"空位，表示之后还会有别的类型 |
| | 算法 | 选了任务类型才出现。带单选的表格，列出能处理这种任务的算法（横向目前是 FoT），比较说明、通信内容和产出，由用户选；最后一行是"更多算法 · 待接入"的空位 |
| 参与方 | 参与方 | 选了算法才出现。带复选框的表格，一行一个参与方，只列出登记了同一场景、同一任务类型数据集的参与方：参与方、数据集、样本数、运行位置、状态。不预先勾选，整行可点，表头可以全选；每方出一份数据集，名下有几份时在行里的下拉框选用哪一份。还不能参加的（等待连接、离线）排在后面，行里有"查看"。右上角"新增数据集""新增参与方"打开新增页，保存后回到这里；新数据集的场景和任务类型与任务一致、持有方在线时直接选入 |
| 运行配置 | 运行方式 | 选项按钮：试跑 / 正式运行；试跑时在右边填每个数据集取几条样本 |
| | 轮次 | 选项按钮：2–6 轮；点字段名旁的"说明"可以看到"第 1 轮是各方单独作答的本地基线" |
| | 模型 | 只有一个模型可用时直接写出来，参与方和服务端都用它；接口待配置时旁边有"去配置"，配好后回到这里。有多个模型时分成参与方模型、服务端模型两个下拉（服务端不调用模型的算法没有服务端模型这一项） |
| 高级配置（默认收起） | 算法参数 | 按算法在注册表里登记的参数生成（FoT：经验库条数、经验提取量、每条样本最多上传、汇总重试上限），默认值即推荐值，选项里标"（默认）"；每个参数旁有"说明"，点开才显示解释 |
| | 通用 | 并发数、随机种子；有多个模型时，还可以为某个参与方单独指定模型 |

右侧摘要列出场景、任务类型、算法、参与方、样本、运行方式和模型，下面是预估（由算法在注册表里声明的每一步用量算出）：

- 参与方的调用次数精确计算，服务端给出下限；
- Token、时长和费用按口径估算；费用要设置了单价才显示，"未设置单价"直接链到这个接口的编辑页。

点"创建并试跑"进入任务详情，顶部提示"已创建…，开始试跑"。正式运行要先确认一次：确认条写明参与方数、样本数、轮次、时长和费用，以及"创建后配置不能修改，运行中可以暂停或取消"。宽屏时确认条出现在配置摘要里，窄屏时出现在底部栏。

"取消"放弃这次的配置回到任务列表；动过的配置要先确认。

上次动过配置、没创建就离开的话，再打开时保留原来的配置，顶部提示"已恢复上次没填完的配置"；"清空重填"要先确认。没动过的草稿不保留：每次打开都从头选，默认名称按这次打开的时间生成。从"复制为新任务"进来时提示"已带入“原任务名”的配置"。

### 任务详情

| 标签 | 内容 |
|---|---|
| 概览 | 主要指标（由任务类型决定，数学推理是准确率）的本地（第 1 轮）与联邦（最新一轮）对比、负迁移、产出条数；各参与方的变化图；明细表 |
| 进度 | 各轮进度，步骤名和每步完成后显示的结果都由算法定义（FoT 每轮 6 步）；当前轮显示各参与方进度。通信记录列出各方每轮上传的条数，点数字看内容，整张表只占一个 Tab 停靠点，用方向键移动 |
| 产出 | 算法的产出物，每轮一版（FoT 产出经验库）。发布为应用时先填应用名称（按任务名预填），发布后顶部提示并能直接"查看应用" |
| 配置 | 创建时冻结的任务配置、算法参数、参与方快照；要修改就"复制为新任务" |

有结果时默认打开"概览"，还没有结果时打开"进度"。运行中和暂停的任务在标签下方显示当前步骤和总进度；暂停用黄色，取消用灰色，标签、横幅、步骤和进度条一致。"取消任务"在页面标题下方确认一次。

### 应用

任务产出发布后成为应用，和原平台的"应用"页一样：

- **试用**：输入问题、选模型，"不带应用 / 带应用"并排对比（前端原型只有示例问题的示意结果）。
- **内容**：查看产出的内容。
- **接入**：导出 JSON 放进自己 Agent 的提示词；API 和命令行接入后端后提供（命令只展示，不提供复制）。

应用可以重命名，也可以撤下（先确认）；撤下后产出还在任务里，可以重新发布。

## 参与方和数据集怎么登记

参与方和数据集在同一个页面"参与方与数据"里，按类分开：

- 先按场景分标签：横向联邦 / 纵向联邦 / 联邦迁移，标签上写这一类有几个参与方（规划中的场景写"规划中"）；
- 每个标签一张表，一行是一个参与方在这个场景下登记的一份数据集：参与方、数据集、任务类型、样本数、运行位置、状态、参加过的任务数。任务类型是数据集的一列，不再分组；
- 参与方本身不绑定场景：它在几个场景下有数据集，就出现在几个标签里；同一个参与方的几份数据集排在一起；
- 点开一行看这份数据集的来源、标注和样本示例，参与方的简介和本地连接命令，以及"为这个参与方新增数据集""删除数据集""删除参与方"（内置示例不能删）；手机上每行变成一张卡片，字段名写在值上面；
- 自己登记的数据集可以删除，但每个参与方至少留一份；要删最后一份，就删除参与方。已有任务里的记录不受影响。

**新增参与方**（页面右上角）：先填基本信息，再选运行位置（不预先选），然后登记它的第一份数据集。选好运行位置后，下方写明这一方的数据怎么处理（平台托管：平台能看到数据内容；参与方本地：只上传交换内容）。

**新增数据集**（页面右上角，或参与方详情里的"新增数据集"）：先选属于哪个参与方，再登记。

两处登记数据集的方式一样，每一步都由用户选：

1. 场景：横向联邦 / 纵向联邦（规划中）/ 联邦迁移（规划中）；
2. 任务类型：列出这个场景里有算法能处理的类型（目前是"数学推理"），它决定数据格式和评估指标；最后同样留一个"更多类型 · 待接入"的空位；
3. 数据：平台托管的参与方上传文件，参与方本地的只登记名称和说明。

| | 平台托管 | 参与方本地 |
|---|---|---|
| 谁运行 Agent | 平台 | 参与方在自己的环境运行客户端 `fedagent-client` |
| 数据集在哪 | 上传到平台 | 留在参与方本地，只登记名称和说明；样本数在客户端连上后上报 |
| 模型密钥 | 用平台配置的模型接口 | 用参与方自己的密钥 |
| 离开参与方的内容 | 平台能看到数据集；服务端步骤仍然只用交换内容 | 只有交换内容（FoT 是解题经验），上传前可以逐条审查 |
| 适合 | 公开数据、演示、算法验证 | 真实的跨机构联邦 |

平台托管的数据集是 JSONL 文件，每行一条样本：

- 数据格式由任务类型决定，选好任务类型后写在上传框里。数学推理：`id`、`question` 必填，`answer`（标注）可以没有；不超过 20 MB。
- 文件在浏览器里检查：不是合法 JSON、缺字段、id 重复都会逐行指出（最多列 5 处），可以"改好后重新选择文件"。
- 检查通过后只保存描述（样本数、标注数、样本示例），不保存内容。接入后端后由后端存储。
- 保存按钮不可用时，旁边写着还缺什么；保存后回到列表并展开刚登记的这一行，顶部提示已添加。新登记的排在最前面。

本地参与方保存后显示"等待连接"，详情里有连接命令（客户端还没发布，令牌接入后端后签发，所以只展示、不提供复制）。连上平台后状态变为"在线"，它的数据集才能在新建任务里选。

## 管理员：算法和模型接口

- **算法**：列出注册表里的算法，以及每个算法适用的场景、任务类型、通信内容和产出；点开一行看每轮步骤、参数默认值和来源论文。新算法以插件登记（见 ARCHITECTURE.md），页面不用改。纵向和迁移的算法待接入，合成一行写明。
- **模型接口**：平台侧的模型调用都通过 OpenAI 兼容的 LLM API。现在只预留一个"默认 LLM 接口"，具体服务和模型之后再配置；接口没配置也能创建任务。接口列成表格；新增、编辑是独立页面，接口地址和模型必填（不填新建任务时选不到它的模型），单价可选；登记的接口可以删除，预留的默认接口不能删。API 密钥只保存在服务端，前端不保存。

## 规则

- 场景未选、所选场景的算法还在规划中、少于 2 个可用参与方、模型接口不存在、轮次超出算法允许的范围时，不能创建任务。
- 数据集只能用于同一场景、同一任务类型的联邦任务；每个参与方在一个任务里只出一份数据集。
- 创建时冻结配置和参与方快照；之后删改参与方和数据集不影响已有任务。
- 运行中可以暂停；暂停后可以继续；取消后停在当前步骤，不能再继续。
- 每轮末尾生成一版产出，最后一版是最终成果；任意一版都可以发布为应用，同一版只发布一次。
- 本地参与方连上客户端之前不能加入任务。
- 不可逆的操作都在原地确认一次，不用浏览器弹窗：取消任务、删除参与方、数据集和接口、撤下应用、重置演示数据、放弃或清空新建任务的配置。

## 原型里哪些是模拟的

- **任务运行**：是加速的模拟，几十秒就能跑完。每一步的真实耗时以预估为准。
- **指标、上传内容、产出、token 用量**：都由任务 id 确定性生成，刷新后不变。侧栏（窄屏在顶栏）始终标着"示例数据"。FoT 的解题经验和经验库是英文，因为 FoT 的提示词是英文。
- **应用试用的对比回答**：是说明用的示意，不是真实模型输出。
- **真实执行的部分**：数据集检查在浏览器里真实执行，导出 JSON 真实生成文件。
- **数据保存**：所有演示数据保存在浏览器本地（localStorage）；侧栏底部（窄屏在页面底部）可以重置。
